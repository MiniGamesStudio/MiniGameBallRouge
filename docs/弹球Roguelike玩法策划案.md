## 0. 文档说明

### 0.1 玩家一眼要看到的东西

**一句话**：我在屏幕下方操控一个球，自动打出有限的 5 发子弹；子弹在敌人和墙之间乱弹，撞到我身后的底墙就飞回来让我接住再打出去；敌人从上往下一排排压过来，清不掉就俯冲撞我；每杀一个敌人攒经验，升级时从 3 个随机技能里选 1 个；我死了就出去用攒的魂晶点永久天赋。

**敌人外观 = 品质底图（整只一张、铺满占格）+ 怪物图（contain 适配叠加）**：

1. 底图 128×128 正好一格，**整只敌人只放一张、拉伸铺满整个占格**（用户拍板：接受横向拉长变形）。一张底图把「占格」整体视觉化，和「占格即血条」的判定口径一致；底图走**九宫格**（`Sprite.Type.SLICED`，切边 `baseSliceInset`=16px）：拉伸时四角与描边按 1:1 保留、只拉开中间；⚠️ 需先把该 spriteFrame 的 `packable` 置 false，否则进动态图集后九宫格失效；
2. **怪物图按体型分两种放法**（`BattleView.spawnEnemy`）：
   - **一格 / 两格** → **一格一张**：两格怪两格各放一张（同一只怪，把占格铺满），每张按美术自身长宽比 contain 适配到该格内（`artFitMargin` = 0.92），四周留一点边让底图露出来当"边框"；
   - **4 / 6 / 8 格** → **一张放大图**：`Boss_001`-`003` 按体型取图，contain 到整个占格（margin 给 1，尽量占满且不拉变形）；
3. 普通与精英按敌人 `defId` 稳定散列到 `monster_0001-0010`（同一只怪每次生成长得一样）。品质 6 色 × 怪物 10 张 = **60 种外观组合**；
4. 受击闪白只闪**怪物轮廓**（底图不闪），模板尺寸用适配后的实际尺寸，不能用占格尺寸（会错位）；因为一格 / 两格是"一格一张图"，**每条怪物图各挂一条受击表现**（两格怪两格同时闪白 + 各自震动），4/6/8 格只有一条。
> 掉落物没有水晶素材，用 Graphics 画圆代替：经验蓝、金币黄、魂晶紫、超级水晶粉。

> **本轮实测发现并修掉的三个坑**（都是"看不见/看不清"类问题，记在这里免得再踩）：
> ① **占位美术完全不显示**：图片在 Cocos 里是「图片资源 + spriteFrame 子资源」两级结构，按图片路径取 `SpriteFrame` 未必取得到，必须按「原路径 → `路径/spriteFrame`」两段兜底（与 `engine/ui/UIBase.ts` 加载按钮图标一致），再不行就绕过 `ResManager` 直接走引擎原生 `bundle.load`。另外**缺图必须画一个可见的洋红方块**：原来缺图只是 `spriteFrame = null`，画面上什么都没有，看起来就像"素材根本没被用上"。素材改为常驻缓存，避免"用逻辑路径去释放实际命中路径"导致贴图提前失效。
> ② **敌人重叠**：行入场间隔原来写死 0.5 s，而第 1 波下落速度只有 25 px/s —— 新行出生时上一行才下落 20px（行高 128px），两行直接糊在一起。现在行间隔由「本带行数 × `rowGapCells`(1.2) × `cellSize` ÷ 当前波下落速度」推出，行距恒为 153.6px（行间留 25.6px 空隙）；出生带的**顶边**对齐出生线，两格大怪不再往上顶半格；带内错峰改为**按列**分配（同一列所有敌人共享同一延迟 → 同列纵向间距恒为整格），并把上一带的最大错峰延迟补进跨带时钟（否则"少落一段"的敌人会和新带贴住：竖版 BOSS 让带高变成 3~4 行后实测只剩 124px < 一格 128px）；跨带推进按 `max(本带行数, 上一带行数)` 计。
> ③ **受击闪白形状不对**：最初按占格画白色圆角矩形，但贴图四周有透明留白，白块把留白一起盖住，看起来像"贴了个白方块"而不是"这只怪被打白了"。现在把精灵自己的 `spriteFrame` 设成 `Mask` 模板（`SPRITE_STENCIL`）再在模板内填白，白色只落在 alpha ≥ 0.1 的轮廓内；坑点是**必须先设 `type` 再设 `spriteFrame`**（内部模板 Sprite 在设 `type` 时才创建），且要把内部 Sprite 的 `sizeMode` 钉成 `CUSTOM`。

**已实现（P0）**：双指操作（拖玩家 / 拖游标，游标贴玩家外围圆旋转（半径 = 玩家图显示半径 + 5px），玩家与浮标层级**恒在敌人 / 子弹 / 掉落之上**）、自动开火与弹匣账本、子弹弹射与底墙回身与主动接弹、防穿模子步进与命中去重、敌人逐行生成（品质底图整只一张、九宫格拉伸 + 怪物图叠加，带缩放弹出动画）与缓慢下落、越线 1 s 判定与俯冲（放大 → 缩小 → 命中判定）、经验水晶掉落与磁吸拾取、升级三选一（满级不出现、连升连弹）、开局天赋三选一、波次推进与过关 / 失败结算、HUD（血量 / 弹匣 / 波次 / 等级经验条）、受击反馈（敌我闪白 + 敌人轻微震动）。

# 第一部分 · 玩法总览

## 1. 一句话定位

**用「会弹射、必须自己飞回来」的子弹，打一堵会压下来、还会还手的敌人墙。**

- 玩家在屏幕下方，靠移动走位，自动开火（**第一行敌人出生动画结束、开始下移之前不发射**，解锁后换波不再重新锁）；
- 子弹有限（初始 5 发），在敌人和四周墙体之间反复弹射，**撞到玩家身后的底墙才回身**，飞回玩家被接住后才能再打出去；
- 敌人**逐行**从屏幕顶部生成、缓慢下移；越到底线后等 1 秒，然后俯冲撞向玩家；
- 每击杀一个敌人掉经验水晶，升级时从 **3 个随机技能**里选 1 个（学新技能或升级已有技能）；
- 玩家血量归 0 → 本局结束 → 结算魂晶 → 回到外围养成（加点 + 皮肤）。

## 2. 核心体验与三条设计支柱

| 支柱 | 设计内容 | 为什么必须守住 |
|---|---|---|
| **① 弹药是空间决策** | 弹匣容量固定、子弹永远不消失、只有回到玩家身上才能再用；底墙是唯一的"回家通道" | 玩家的每一次开火都在问"子弹会飞到哪里？我还能不能接住？"。**这是本作区别于普通射击游戏的核心** |
| **② 敌人是"压下来的墙"** | 敌人以整行排列、刚性整体下移，不是零散小怪；越线后有 1 秒判定窗再俯冲 | 形成"倒计时压迫感"：清墙速度直接等于生存时间，不存在绕开这个选项 |
| **③ 成长由击杀驱动** | 升级**只**来自击杀掉落的经验水晶（不再按波次定时给） | 打得好 → 升级快 → 更强 → 打得更好，正反馈归玩家；而不是"熬时间自动变强" |

> **明确废弃的旧设定**：早期版本"每过一波自动升 1 级 / 每波三选一"的**时间驱动**升级已废弃（旧 §26.9-Q5）。波次仍然存在，但只作为**关卡节奏单位**（敌人分批生成的分段）和难度曲线的自变量，**不再触发升级**。

## 3. 一局游戏的完整流程

```
①  开局：从 3 个随机天赋中选 1 个（§10）→ 天赋立即生效，游戏开始
        ↓
②  敌人按关卡配置逐行从屏幕顶部生成（每行有缩放弹出动画，行间错峰入场）（§9.2）
        ↓
③  敌人缓慢下移；带攻击手段的敌人边走边打（射箭 / 子弹 / 激光 / 直线冲击，均带预警）（§8）
        ↓
④  玩家自动开火（**开火解锁**：第一行敌人出生并开始下移之前不发射，之后永久放行）→ 子弹在【敌人】与【四周墙体】之间弹射（不消失、不衰减）（§6）
        ↓
⑤  子弹撞到玩家【身后的底墙】→ 回身飞向玩家 → 玩家接住（移动到轨迹上或等它飞回来）
        → 子弹回到弹匣 → 可再次发射
        ↓
⑥  击杀敌人 → 以敌人位置为圆心、半径 0.2 格随机方向散落掉落物
        （经验水晶 / 金币；精英、BOSS 额外掉超级水晶、魂晶）（§11）
        ↓
⑦  经验累积满 → 暂停战斗并弹出【3 选 1】：学新技能 或 升级已有技能
        （可用金币刷新候选、直接购买技能；可用超级水晶升级/进化/融合技能）（§11.4、§12.4）
        ↓
⑧  敌人越过底线 → 等待 1 秒判定窗 → 放大动画 → 快速飞向玩家（飞行中缩小）
        → 抵达玩家位置消失并造成伤害（§9.4、§9.5）
        ↓
⑨  玩家血量归 0 → 本局结束 → 结算面板（存活时间 / 击杀数 / 获得魂晶）
        → 魂晶进入外围养成（§18 加点、§19 皮肤）（§13）
```

## 4. 操作方式

全屏触摸层统一接管，**双指可同时操作两个目标**（操作方案 A，详见 **附录 J**）：

| 操作 | 触发条件 | 说明 |
|---|---|---|
| **移动玩家** | 按下点到**玩家中心**的距离 ≤ `playerGrabRadius`（**74 px**） | 相对跟随（按按下瞬间的偏移量拖动），点哪里都不会瞬移；**按在玩家身上不会改变瞄准方向** |
| **调整射击方向** | 除"按住玩家"之外的**其它任意位置**点击 / 拖动 | 按下**立即生效**（点一下就把瞄准点设到按下点），继续拖动持续调整；瞄准方向 = 玩家 → 瞄准点 |
| **开火** | 全自动 | 每 `fireInterval` 一发，方向 = 玩家 → 瞄准点 |
| **兜底自动瞄准** | **瞄准触摸**空闲 `autoAimDelay`（**2.0 s**）后自动接管 | 自动锁定**最近的可命中敌人**；**拖动玩家不打断**，任意瞄准触摸立即交回手动 |
| **主动接弹** | 无需按键 | 玩家移动到子弹轨迹上，与子弹碰撞即完成回收（= 碰撞检测，**不需要额外操作**） |

- 两个触摸用**独立 id**：玩家触摸只走"移动玩家"分支、瞄准触摸只走"调整方向"分支，互不抢占 → **一手按住玩家走位、另一手在任意处调角度可同时生效**；
- 单指时"按哪里"就决定干什么：**按在球上 = 走位，按在别处 = 瞄准**（不再有"必须先抓住浮标"这一步）；
- 玩家移动范围夹在设计区域内（用 `playerHitRadius` 留边）；瞄准点同样夹在屏幕内（用浮标外接圆半径 45 px）；
- **瞄准浮标已降级为纯"方向标识"，不可拖动**：仍贴在玩家外围圆上（半径 = 玩家图显示半径 + `cursorOrbitGap`），玩家贴近屏幕边缘时会被压回屏内保证可见；它只表示方向，**抓取判定已删除**（`isPressOnCursor()` / `CURSOR_GRAB_BAND`）；
- 另有**瞄准辅助射线 + 首段反弹射线**（从玩家中心沿瞄准方向画到**最近的墙或敌人**、再按真实反射方向续画一段；**遇墙与遇敌都会反射**，底墙不反射），与真实弹道同源，见 **附录 J**（J-4 规则 / J-7 为什么不是玩法改动）；
- 设计意图：把"走位"和"瞄准"彻底拆成两根手指，且瞄准**不再需要先抓住浮标**（任意处按下即是瞄准），单手也能玩（先按住球走位，抬手后在别处点一下调方向）；无人瞄准 2 s 后自动接管，避免"忘记瞄 = 一直打空"。

## 5. 场地、坐标与度量单位

| 项 | 值 | 说明 |
|---|---|---|
| 设计分辨率 | **750 × 1334** | 横屏不考虑 |
| **格（cell）** | **128 × 128 px** | 全部体型与掉落距离的**基准单位**。品质底图素材（`white`/`green`/…）的原始尺寸，一格一张，精灵不缩放 |
| 棋盘列数 | **5 列** | 棋盘宽 640 px，居中于 750，左右各留 55 px |
| 坐标系 | 原点在屏幕中心 | 底边 y = −667，顶边 y = +667 |
| 敌人出生线 | 生成带的**顶边** y = **+667**（= 棋盘顶部第一格） | 单格敌人盒子 = [667, 795]，下落 1px 即露头 |
| **俯冲线 / 底线** | y = **−567**（距屏幕底 100 px） | 敌人**自身矩形底边**越过此线即进入判定流程（§9.4） |
| 玩家出生点 | 距屏幕底部 **120 px** | |
| 墙体 | 屏幕四周边缘 | 子弹撞墙镜面反弹；**底墙**是唯一触发"回身"的墙（§6.3） |

> **为什么是 5 列**：最大的 BOSS 占 8 格 = 2 列 × 4 行（§7.4 四/六/八格一律竖版：2×2 / 2×3 / 2×4），必须留出至少 1 列余量让玩家有绕行空间，所以棋盘取 5 列。列数是**可配置项**，但改动会同时影响关卡排布与难度，需回归 §25 的平衡校验。

# 第二部分 · 核心机制

## 6. 子弹：弹射与回收【需求 1】

### 6.1 规则总览

| 规则 | 内容 | 可配置项 |
|---|---|---|
| **初始数量** | 开局 `bulletCount = 5` 发（可通过升级、技能、外围加点增加） | `PlayerDef.bulletCount` |
| **弹射** | 子弹在**敌人**与**四周墙体**之间反复弹射，**不消失、不衰减、不掉速** | —— |
| **回身触发** | 子弹撞到玩家**身后的底部墙**（玩家位于屏幕下部）→ 立即转为"回身"状态，锁定玩家直飞 | —— |
| **回收** | 回身的子弹抵达玩家判定半径内即被回收，**返还弹匣**，可再次发射 | `catchRadius` |
| **主动接弹** | 玩家移动时与任意在外的子弹相交即回收（提前回收，无需等它撞底墙） | `catchRadius` |
| **兜底** | 子弹存活超过 `maxBulletLife` 仍未回收 → 强制转入回身状态 | `maxBulletLife`（建议 8 s） |

**一句话记住三条铁律**：

1. **子弹有限且循环使用** —— 撞敌人、撞墙**都只反弹不消失**，只有**飞回玩家身上才回收**。`bulletCount` 就是弹药上限，场上没有余弹时打不出去。
2. **子弹撞到底墙必定回家** —— 撞到屏幕**底边**就转入回身状态、锁定玩家直飞，玩家一边移动也不会 miss。顶墙、左右墙、撞敌人**都只反弹不回身**。
3. **回身中的子弹穿过敌人、不结算伤害** —— 一是"必定回身"不能被半路挡下来，二是避免子弹卡在敌人身体里被反复结算。

> **为什么必须有铁律 2**：没有它，斜着打出去的子弹会永远在墙角之间折返，子弹再也回不来，弹匣直接死锁。设计上的比喻是：**球落到地上，就该滚回玩家手里。**

### 6.2 弹射规则

| 碰撞对象 | 速度处理 | 伤害处理 | 备注 |
|---|---|---|---|
| **顶墙 / 左墙 / 右墙** | 标准镜面反射：只翻转撞到那条轴的速度分量 | 无 | —— |
| **底墙（玩家身后）** | 不反射，转入**回身**状态 | 无 | 见 §6.3 |
| **敌人** | 沿**穿透更浅的那条轴**弹开（等价于撞在最近的边上），子弹不消失 | 按 `bulletDamage` 结算一次 | 见 §6.4 去重规则 |
| **玩家（捕捉圈内）** | 仅在 `armed = true` 时回收 | 无 | 见 §6.3 |

**子步进防穿模**：子弹速度高（900 px/s，60 fps 下约 15 px/帧），必须把每帧位移拆成若干小步逐段检测（单步 ≤ 8 px，单帧最多 16 步），否则会直接穿过薄敌人或多格敌人的边角。

### 6.3 回身、回收与主动接弹

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| `flying`（飞行） | 出膛 | 直线飞行 + 弹射 | 撞底墙 → `returning`；进捕捉圈且 `armed` → 回收 |
| `returning`（回身） | 撞到底墙 / 超时兜底 | **锁定玩家当前位置直飞**（每帧更新目标点），穿透敌人不结算伤害、不反弹 | 进入捕捉圈 → 回收 |
| 回收 | 进入 `catchRadius` 且 `armed == true` | 返还弹匣，节点回收进对象池 | —— |

**关键细节**：

- **`armed` 标志**：子弹必须先"离开过"玩家捕捉圈才允许被回收，否则刚出膛的第一帧就会被自己收回去。
- **回身时强制 `armed = true`**：子弹完全可能在捕捉圈**内部**撞到底墙，不强制置位就会永远贴着玩家打转、回收不掉。
- **捕捉半径** `catchRadius = 玩家判定半径 + 子弹半径`（建议 `28 + 10 = 38`，若沿用旧实现的视觉半径 40 则为 `55`）——**判定半径建议缩小到 24~28 px**，视觉不变但手感明显变好（理由见 §8.6）。
- **主动接弹 = 移动拦截**：玩家不需要任何额外按键或判定窗口，移动到子弹轨迹上即可提前回收。这条规则让"走位"同时承担"输出"和"补弹"两个职责，是玩法的乐趣来源之一。

### 6.4 碰撞与伤害去重（多段命中的前提）

| 规则 | 说明 |
|---|---|
| **每次接触只结算一次** | 一发子弹在一次接触窗口内命中同一敌人**只扣一次血**，用 `hitSet` 去重 |
| **为什么必须去重** | 每小步 ≤ 8 px，一个 80 px 的敌人要 10 个小步才能穿完；不去重就会"一次穿过扣 10 次血" |
| **重复命中敌人** | 子弹被弹开后再次撞上同一敌人（例如在墙缝里来回弹），**应再次结算**——去重集合在窗口结束时清空 |
| **穿透/回身窗口** | 若技能提供"穿透窗"（§12.3），窗口内不反弹、继续穿行，命中目标全部记入 `hitSet` 防重复 |

### 6.5 僚机与额外弹源（免费弹账本）

| 项 | 规则 |
|---|---|
| **独立账本** | 僚机、分裂弹等"赠送弹"**不占玩家弹匣**，但同样会弹射 / 命中 / 回身 / 被回收 |
| **硬上限** | 免费弹全局上限（建议 **8 发**）。因为"近水平"的子弹可能永远落不到底、也就永远回不来，没有上限会导致节点无限堆积 |
| **回收归属** | 回收时先在玩家弹匣账本里找，再在免费弹账本里找；两个账本都空时该子弹节点才真正休眠 |
| **设计目的** | 让"提升火力密度"的技能有意义（绕过弹匣天花板），同时不破坏"弹药有限"的核心手感 |

### 6.6 配置项（`PlayerDef` + `GameTuning`）

| 参数 | 键名 | 建议初始值 | 说明 |
|---|---|---|---|
| 弹匣容量 | `bulletCount` | **5** | 升级 / 技能 / 外围加点可提升 |
| 开火间隔 | `fireInterval` | **0.35 s** | 有余弹时最多攒一发，不会连突 |
| 子弹速度 | `bulletSpeed` | **900 px/s** | |
| 子弹伤害 | `bulletDamage` | **10** | 受攻击力类技能与加点影响 |
| 子弹半径 | `bulletRadius` | **10 px** | |
| 回收半径 | `catchRadius` | **38 px**（判定半径 28 + 10） | 玩家主动接弹与回身回收共用 |
| 最长存活 | `maxBulletLife` | **8 s** | 超时强制回身（兜底） |
| 回身速度倍率 | `returnSpeedScale` | **1.0** | 可被技能提升（如"磁力回收"） |
| 免费弹上限 | `freeBulletMax` | **8** | 僚机 / 分裂弹共用 |
| 单帧子步上限 | `maxSubStepDistance` / `maxSubStepCount` | **8 px / 16** | 防穿模 |

### 6.7 设计意图与可调空间

**为什么弹匣是唯一限流手段**：如果子弹无限，玩家就只需要考虑"打哪儿"；有了弹匣，"子弹什么时候回来"变成一个**空间问题**——玩家要同时考虑打哪、以及子弹会不会飞到自己够不到的地方。这是本作的核心差异化。

**已知的张力点（需在数值阶段守住）**：

| 张力 | 现象 | 处理方向 |
|---|---|---|
| 弹匣在近距离可能不构成约束 | 墙贴近玩家时，子弹往返周期极短，射速（`fireInterval`）而非弹匣成为瓶颈 | 通过**射速/弹匣联动调整**或"回弹路径也算输出"的技能让回收节奏全程有意义（候选方案见附录 C） |
| 子弹空转 | 子弹从墙的左右两侧飞过时不命中任何东西，占着弹匣 | 用命中/空转的**视觉与音效区分**降低挫败；`maxBulletLife` 保证不会永久丢失 |

## 7. 敌人：品质 × 类型 × 体型【需求 2】

### 7.1 三轴模型总览

敌人由**三个正交轴**定义，再叠加**攻击手段**。这样可以用一张数据表生成全部组合，**不需要为每种敌人写代码**：

```
敌人 = 品质(6 色)  ×  类型(4 类)  ×  体型(5 种占格)
                     +  攻击手段(0~4 种，含预警)
```

**总血量公式**：

```
HP = 品质单格血量 × 占格数 × 类型血量倍率 × 难度血量倍率
```

> 示例：红色(150) 8 格大BOSS(×15) 在第 10 波（难度 ×2.08）= `150 × 8 × 15 × 2.08 = 37,440` HP。
> ⚠️ 这是**待平衡值**：必须与玩家实际 DPS 一起回归（§25），大BOSS 的血量应以"一场 30~60 秒的 BOSS 战"反推，而不是照搬倍率。

### 7.2 轴 1：品质（6 色，决定血量与稀有度）

| 品质 | 颜色 | 单格血量 | 相邻倍率 | 生成权重 | 经验 | 金币 |
|---|---|---|---|---|---|---|
| 白 | ⚪ 白 | **12** | —— | **30** | 1 | 1 |
| 绿 | 🟢 绿 | **20** | ×1.67 | **25** | 2 | 2 |
| 蓝 | 🔵 蓝 | **35** | ×1.75 | **20** | 4 | 3 |
| 紫 | 🟣 紫 | **55** | ×1.57 | **13** | 8 | 6 |
| 金 | 🟡 金 | **90** | ×1.64 | **8** | 16 | 12 |
| 红 | 🔴 红 | **150** | ×1.67 | **4** | 32 | 25 |

**设计规则**：

- 血量按**几何级数**递增（约 ×1.65/级），保证"高一档明显更硬"且**可预测**（玩家能建立"紫怪很硬"的直觉）；
- 生成权重递减，红怪稀有 → 见到红怪 = 小高潮；
- 品质同时决定**掉落档位**（经验、金币，见 §11.2）。

### 7.3 轴 2：类型（4 类，决定行为与掉落）

| 类型 | 行为特征 | 攻击手段数 | 血量倍率 | 经验倍率 | 掉落加成 |
|---|---|---|---|---|---|
| **普通** | 只下移，**默认不主动攻击**（可配置为带 1 种手段） | 0 ~ 1 | ×1 | ×1 | 经验、金币 |
| **精英** | 下移 + 间歇攻击 | 1 ~ 2 | **×2.5** | ×3 | \+ 超级水晶（低概率，建议 15%） |
| **小BOSS** | **停下移动**释放技能，放完继续走 | 2 ~ 3 | **×6** | ×8 | \+ 超级水晶（100%）、魂晶 ×3 |
| **大BOSS** | 停下 + **多阶段**（血量分段改变技能与属性） | 3 ~ 4 | **×15** | ×20 | \+ 超级水晶 ×2、魂晶 ×10 |

**行为规则**：

- **普通敌人默认不攻击**，且"是否攻击"是**纯配置项**（`attack.kind = None` 或 `attack.enabled = false`）。这样前期不会被弹幕压垮，后期难度靠"**攻击型敌人占比**"爬升，而不是靠无脑堆数量；
- **精英**：按 `attackInterval` 间歇释放，移动不停；
- **小BOSS / 大BOSS**：`stopToCast = true` —— 进入攻击状态时**停止下移**，播放蓄力/施法表现，放完继续下移。停下期间仍占用墙内位置、可被击杀；
- **大BOSS 的多阶段**见 §8.4。

### 7.4 轴 3：体型（决定占格与像素尺寸）

| 体型 | 占格 | colSpan | rowSpan | 像素尺寸 | 默认类型倾向 |
|---|---|---|---|---|---|
| **单格** | 1 | 1 | 1 | 128 × 128 | 普通 / 精英 |
| **双格横** | 2 | 2 | 1 | 256 × 128 | 普通 / 精英 |
| **双格竖** | 2 | 1 | 2 | 128 × 256 | 普通 / 精英 |
| **四格** | 4 | 2 | 2 | 256 × 256 | **小BOSS** |
| **六格** | 6 | 2 | 3 | 256 × 384 | 小BOSS / 大BOSS |
| **八格** | 8 | 2 | 4 | 256 × 512 | **大BOSS** |

**硬性约束（模型地基）**：

1. **行数上限 = `maxEnemyRowSpan` = 4**（旧的「所有体型 rowSpan ≤ 2」已被竖版 BOSS 推翻）：4/6/8 格的 rowSpan 是 2 / 3 / 4，会超出原来固定的"2 行带"。装箱逻辑改成**按体型真实行数开带**（`WaveBuilder.buildBigBand`：`bandRows = bigRows`），带高 1~4 行；
2. **4 / 6 / 8 格即 BOSS 档**（需求原文），且**一律竖版**：占 2 列 × 2/3/4 行。棋盘 5 列，所以大怪左右还各留 3 列给玩家绕行 —— 靠"高"制造压迫感，不再靠"宽"霸屏；
3. 竖版现在覆盖 **2 格与 4/6/8 格**（2×1 / 1×2 与 2×2 / 2×3 / 2×4）。旧实现里竖版双格是**把横版 256×128 旋转 90°** 实现的（碰撞盒宽高对调），这个技巧只适用于 2 格；4/6/8 格的竖版跨度直接写在 `SHAPE_SPAN` 里。

### 7.5 类型 × 体型 映射矩阵（默认值，可配置）

| 体型 \ 类型 | 普通 | 精英 | 小BOSS | 大BOSS |
|---|---|---|---|---|
| 单格 | ✅ 默认 | ✅ | ✖ | ✖ |
| 双格横 / 双格竖 | ✅ 默认 | ✅ 默认 | ✖ | ✖ |
| 四格 | ✖ | ⭕ 可选 | ✅ **默认** | ✖ |
| 六格 | ✖ | ✖ | ✅ 默认 | ⭕ 可选 |
| 八格 | ✖ | ✖ | ⭕ 可选 | ✅ **默认** |

- ✅ = 默认组合，⭕ = 允许但需单独配置，✖ = 不允许；
- 矩阵是**数据表里的开关**，不是代码里的 if。关卡配置可以临时放一个"精英八格"作为特殊演出。

### 7.6 敌人生成权重与随机

| 项 | 建议值 | 说明 |
|---|---|---|
| 品质权重 | 白 30 / 绿 25 / 蓝 20 / 紫 13 / 金 8 / 红 4 | 见 §7.2 |
| 类型权重 | 普通 78 / 精英 18 / 小BOSS 3 / 大BOSS 1 | **可按关卡覆盖**；BOSS 一般由关卡手动指定而不是随机抽 |
| 体型权重 | 单格 6 / 双格横 3 / 双格竖 3 / 四格 1 / 六格 0.5 / 八格 0.3 | 大体积稀有；权重与"放不放得下"共同决定最终结果 |
| 随机种子 | `seed`（关卡级） | **同一 seed 必须可复现**，用于每日挑战与回归测试 |

### 7.7 排布规则：双行带模型（装箱）

**带（band）的定义**：一个带 = **2 行 × 5 列 = 10 格**。

```
一个带（10 格预算）
┌─────────────────────┐
│ .  .  .  .  .       │  row 0
│ .  .  .  .  .       │  row 1
└─────────────────────┘
```

| 规则 | 说明 |
|---|---|
| **一次生成一个带** | 带内每个敌人有 `spawnStagger`（建议 0.08 s）错峰，做出"逐个弹出"的缩放动画；**按列**错峰（同列共享延迟，同列纵向间距才不会被吃掉） |
| **带间不重叠** | 带高按本带最高的敌人开（1~4 行），所以同一只敌人不会跨到下一带 |
| **装箱顺序** | 按 `colSpan` **降序**放置（大块先放），避免"小块占位导致大块放不下" |
| **大怪优先（重要）** | 若按 col 0→4 顺序填充，大怪容易被**静默降级**成小怪，等于 4/6/8 格不存在（竖版大怪只占 2 列，横向比原来好塞）。必须**先单独走一趟"大怪优先"的放置**，再填小怪 |
| **降级链** | 放不下时的降级规则要写成"**所有放得下的形状，按跨度降序**"，而不是硬编码 `[抽中的, 横版双格, 单格]`（硬编码会出现同一形状被尝试两次的无效尝试） |
| **兜底** | 一个带一个敌人都放不下时，至少塞 1 个单格，保证每带非空 |
| **整面墙刚性下移** | 同一波内所有敌人同速下降，相对位置永久保持 —— 这是"墙"的手感来源 |

**容量对照表（10 格预算的合法组合）**：

| 组合 | 占用 | 余量 |
|---|---|---|
| 10 × 单格 | 10 | 0 |
| 5 × 双格横 | 10 | 0 |
| 1 × 八格 + 1 × 双格竖 | 8 + 2 = 10 | 0 |
| 1 × 六格 + 1 × 四格 | 6 + 4 = 10 | 0 |
| 1 × 六格 + 2 × 双格横 | 6 + 2 + 2 = 10 | 0 |
| 2 × 四格 + 1 × 双格横 | 4 + 4 + 2 = 10 | 0 |
| 1 × 八格 + 2 × 单格 | 8 + 1 + 1 = 10 | 0 |

> 八格敌人（2 列 × 4 行）把带加高到 4 行，旁边还留 3 列 —— 竖版让大怪"高"而不是"宽"，既保留压迫感又不堵死玩家走位。

## 8. 敌人攻击手段与 BOSS 技能【需求 2】

### 8.1 四种攻击手段

| 手段 | 枚举值 | 行为 | 预警 | 关键参数 |
|---|---|---|---|---|
| **射箭** | `Arrow` | 朝**玩家当前位置**射一支箭（有飞行时间，可走位躲） | **0.4 s** 瞄准线 | 箭速 / 伤害 / 间隔 |
| **发射子弹** | `Shoot` | 扇形连发（默认 3 发，±15°） | 无（快，靠弹速本身可躲） | 弹速 / 伤害 / 间隔 / 发散角 / 连发数 |
| **激光** | `Laser` | 蓄力后打出一条光束（横 / 竖） | **0.8 s** 红光 | 伤害 / 持续 / 光束宽度 |
| **直线冲击** | `Charge` | 朝玩家方向直线冲刺（撞墙或飞完距离后停下） | **0.6 s** 后仰 | 冲刺速度 / 伤害 / 距离 |

**参数表（`EnemyDef.attack`）**：

| 字段 | 说明 |
|---|---|
| `kind` | `None / Arrow / Shoot / Laser / Charge` |
| `enabled` | 是否启用攻击（`false` 时该敌人只下移） |
| `range` | 触发距离（玩家进入该距离才攻击） |
| `interval` | 攻击间隔（秒） |
| `damage` | 单次伤害 |
| `windup` | 预警时长（秒）——**必须 > 0**，除"发射子弹"外 |
| `speed` | 弹速 / 冲刺速度 |
| `count` / `spreadDeg` | 连发数 / 发散角（扇形用） |

### 8.2 预警设计原则（生命线）

> **预警时间是这类玩法的生命线。** 玩家在同一时间还要接子弹、选落点、看墙的位置，没有清晰预警就会变成"莫名其妙掉血"。

| 原则 | 要求 |
|---|---|
| **所有攻击必须有可见预警** | 除"发射子弹"外，`windup` 不得为 0；激光必须红光蓄力 |
| **预警与被预警对象绑定** | 瞄准线/红块指向**玩家当时位置**，且**不跟踪**（给走位留出空间） |
| **预警时长可配置** | 每种手段的 `windup` 都是表字段，可按关卡/难度上调 |
| **预警与伤害一一对应** | 视觉出现 = 一定会打出来（不做假动作）；反之不允许"无预警伤害" |

### 8.3 攻击触发与移动关系

| 类型 | 移动 | 攻击 |
|---|---|---|
| 普通（默认） | 常驻下移 | 无 |
| 普通（配置带攻击） | 常驻下移 | 进入 `range` 后按 `interval` 攻击 |
| 精英 | 常驻下移 | 进入 `range` 后攻击，**移动不停** |
| 小BOSS | 常驻下移 | 进入攻击状态 → **停止下移** → 释放 → 恢复下移 |
| 大BOSS | 常驻下移 | 停止下移 → **按阶段释放多段技能** → 恢复下移 |

- 攻击**不打断下移之外的任何系统**：停下的敌人仍在墙内占位、仍会被子弹命中；
- 停止释放必须有**明显视觉表现**（描边、蓄力特效、身体微缩放），否则玩家会误判它已脱离墙；
- **建议不打断 BOSS 施法**（受伤不眩晕），避免"高射速玩家永久锁死 BOSS"的退化玩法。

### 8.4 BOSS：停下释放与多阶段

**大BOSS 阶段表（建议模板，可配置）**：

| 阶段 | 血量区间 | 行为 | 技能 |
|---|---|---|---|
| **阶段 1** | 100% ~ 66% | 正常下移，停下释放 | 射箭 + 直线冲击 |
| **阶段 2** | 66% ~ 33% | 下移速度 +20%；停下释放 | 加入激光（横扫）；召唤 2 个单格普通小怪 |
| **阶段 3** | 33% ~ 0% | 下移速度 +50%；攻击间隔 −30%（狂暴） | 全部技能 + 扇形弹幕密度提升 |

**小BOSS 模板**：单阶段，2~3 种手段，`stopToCast = true`，停下 1.5~2.5 s 释放一轮。

**BOSS 通用规则**：

| 规则 | 说明 |
|---|---|
| **占格即血条** | BOSS 用**自身矩形**作为命中体，整块一起受击、一起俯冲（不是每一格独立） |
| **独立血条** | 出现 BOSS 时 HUD 显示专属血条（§22） |
| **阶段切换必须有演出** | 换阶段时播放 0.5 s 的无敌演出（闪光 + 震屏），给玩家"它变强了"的信号 |
| **俯冲伤害** | BOSS 越线后同样进入判定→俯冲流程，伤害 = `diveDamagePerCell × 占格数`，**必须设上限**（建议 ≤ 40），避免八格怪一击必杀 |
| **击杀奖励** | 掉落超级水晶 ×2、魂晶 ×10、经验按 `×20` 倍率结算（§11.2） |

### 8.5 攻击型敌人占比（难度的主要旋钮）

| 波次区间 | 攻击型敌人占比 | 说明 |
|---|---|---|
| 1 ~ 3 波 | **0%** | 教学期：玩家先熟悉弹射、回收、接弹 |
| 4 ~ 8 波 | 10% ~ 20% | 引入射箭（预警最长、最好躲） |
| 9 ~ 15 波 | 20% ~ 35% | 加入子弹、激光；精英开始成组出现 |
| 16 波以上 | 35% ~ 50% | 加入直线冲击；BOSS 波必带 3~4 种手段 |

> 难度爬升靠**占比**而不是靠"每个敌人都加攻击"：前者玩家能感知"这波有 3 个弓箭手"，后者只会觉得"全场都在打我"。

### 8.6 玩家判定半径（手感关键项）

| 项 | 值 | 理由 |
|---|---|---|
| 视觉半径 | 56 px（`player_001` 80×76 按 contain 适配到 128 格后约 118×112） | 受击判定 45 px 仍小于视觉半径，手感更好 |
| **建议判定半径** | **24 ~ 28 px** | 玩家碰撞体在 750 px 宽的场地里闪避弹幕非常吃力；判定收窄后"擦弹"会变成爽点，而视觉上完全看不出来 |
| 应用范围 | 受击判定、`catchRadius` 计算 | 接弹判定同理（`catchRadius = 判定半径 + 子弹半径`） |

## 9. 关卡推进：生成、下移、判定、俯冲【需求 3】

### 9.1 关卡来源：手写 + 随机，两种都要支持

| 来源 | 说明 | 用途 |
|---|---|---|
| **手写配置** | 关卡表里逐波、逐行写清"这一行放什么敌人"（`RowDef.template`） | 教学关、BOSS 关、演出关 |
| **随机生成** | 按权重抽品质 / 类型 / 体型，用**装箱算法**填满每一带（§7.7） | 无尽模式的主力；也是"每局不同"的来源 |
| **混合** | 同一关卡里，普通波随机、BOSS 波手写 | **推荐的默认做法** |

**确定性要求**：随机生成必须由 `seed` 驱动，**同一 seed 在任意设备上生成完全相同的关卡**。这是每日挑战、排行榜公平性、以及自动回归测试的前提。实现上不允许在玩法逻辑里直接调用 `Math.random()`，必须走可注入的 RNG。

### 9.2 生成与入场

| 环节 | 规格 |
|---|---|
| **生成位置** | 直接在棋盘**顶部第一格**（y = +667）出生并缩放弹出，不再从屏幕外"走进来" |
| **全场停止** | **任意一个**敌人停住不动时（到底站住 Telegraph、或被冰冻 / 眩晕等技能定住 `frozen`），**全场敌人一律停止下落**；该敌人被消灭或恢复后，全场自动恢复移动（`applyStopBlocking` 每帧算 `enemy.blocked`） |
| **排列方式** | 敌人**一行行排列**，棋盘 5 列；同一带的敌人按 `spawnStagger`（0.08 s）**按列**错峰入场（同列共享同一延迟） |
| **入场动画** | 每个敌人播放**缩放弹出动画**：`scale 0.6 → 1.0`，时长 **0.25 s**，带轻微回弹（`backOut`） |
| **行入场间隔** | **不写死时间**：新的一带要出生，先等已出生的内容下落「本带行数 × `rowGapCells`」格，即 `行数 × rowGapCells × cellSize ÷ 当前波下落速度`；`rowGapCells` 默认 **1.2**（一行 128px → 行距 153.6px，行与行留 25.6px 空隙） |
| **带内弹出节奏** | 同一排内左右依次弹出 `spawnStagger`（0.08 s），但总时长受 `spawnStaggerBudget`（默认 0.5，占一个行间隔的比例）约束；**不同排同时出生**，保证"带内保持队形"的刚性 |
| **墙满排队** | 墙行数上限 `maxWallRows = 20`；满时新行**排队等待**，队列**跨波保留**，解堵后不会一次性涌入 |
| **血量结算时机** | 血量在**入场那一刻**按当时的难度倍率结算（排队的行拖到下一波入场时，按**新难度**算血量——这是刻意设计） |
| **换波空窗** | 换波瞬间墙上可能是空的，玩家**仍然要继续累积开火计时**（不允许"没有敌人就不计时"，否则每次换波都白送一个空窗） |

### 9.3 下移与难度曲线

**所有敌人常驻下移**，同一波内**速度恒定**（只在换波瞬间跳变，避免整面墙的速度一直蠕变）。三条难度线**同时线性增长、各自独立封顶**：

| 维度 | 成长公式（第 N 波） | 默认参数 | 封顶 | 封顶波次 |
|---|---|---|---|---|
| **单波行数** | `基础行数 + 1 × (N−1)` | 10 ~ 20 行 | **30 行** | 第 21 波 |
| **下落速度** | `20 × (1 + 0.08 × (N−1))` px/s | 20 px/s | **×2.5 = 50 px/s** | 第 20 波 |
| **血量倍率** | `1 + 0.12 × (N−1)` | ×1.0 | **×2.5** | 第 14 波 |
| **攻击型占比** | 见 §8.5 | 0% → 50% | 50% | 第 16 波 |

> 做成**线性 + 封顶**而不是指数：指数大概在第 10 波就会直接崩掉，而且不好反推某一波到底是多少。线性让"变难"看得见、可预期。
> **波次的作用**：波次只作为**关卡节奏单位**（敌人分批生成的分段）和难度曲线的自变量，**不再触发升级**（升级只来自击杀，§11）。

### 9.4 越线判定：1 秒判定窗

| 阶段 | 规格 |
|---|---|
| **触发条件** | 敌人**自身矩形的底边**越过俯冲线（y = −567）——不是"行"越过，多格敌人按整块算 |
| **判定窗** | 触发后**等待 1 秒**（`diveTelegraph`，可配置）。期间敌人**停在原地**、仍可被击杀、仍在受击判定内 |
| **视觉表达** | 判定窗内敌人闪烁/描边变红 + 播放"蓄势"缩放（`scale 1.0 → 1.15` 往复），并在其下方投出阴影标记 |
| **设计目的** | ①给玩家"最后一击"的机会，避免"到底即死"的挫败；②这 1 秒是**玩家主动接弹/收弹的黄金窗口**，与核心机制咬合 |

### 9.5 俯冲

```
判定窗结束（1s）
   ↓
放大动画：scale 1.0 → 1.35，时长 0.4s（`backIn`，让它看起来"扑出来"）
   ↓
快速飞向玩家：速度 `diveSpeed = 700 px/s`，直线追踪玩家当前位置
   飞行途中同时做缩小动画：scale 1.35 → 0.5
   ↓
抵达玩家位置（进入命中半径 `diveHitRadius = 45 px`）→ 消失（对象池回收）→ 对玩家造成伤害
   ↓
若飞完全程仍未命中（玩家躲开了）→ 飞离屏幕后消失，不再造成伤害
```

| 项 | 值 | 说明 |
|---|---|---|
| 俯冲速度 | **700 px/s** | 可配置 |
| 命中半径 | **45 px**（随帧长取 `max(单帧位移, 45)`） | 高速时必须用单帧位移兜底，否则会穿过去不判定 |
| 俯冲伤害 | **`diveDamagePerCell × 占格数`**，单格 5 → 单格怪 5 点；**上限 `diveDamageMax = 40`** | 多格 BOSS 不能一击必杀 |
| 判定方式 | 距离判定（圆心距 ≤ 命中半径） | 不用物理引擎 |
| 伤害后 | 该敌人**消失**（自爆式），不返回墙 | 这是"墙是计时器"的具象化 |

> **注**：旧实现里单格俯冲伤害是 20（满血 100 → 5 次死亡）。本版改为**按格数**计（单格 5），并把伤害总量交给"越线频率"控制 —— 因为越线频率本身已经由难度曲线管住了，两处同时收太紧会让后期无解。

### 9.6 关卡配置示例

**手写波（造型 + 强度都明确）**：

```jsonc
{
  "id": "L001", "name": "教学关", "seed": 0,
  "waves": [
    {
      "mode": "handwritten",
      "rows": [
        { "template": "e_slime_white|e_slime_white|e_slime_white|e_slime_white|e_slime_white" },  // 满行 5 个单格
        { "template": "e_slime_green|_|e_archer_green|_|e_slime_green" },                        // 空两列做造型
        { "template": "e_gunner_blue|-|_|e_slime_green|e_slime_green" }                          // 双格横：第 0 列锚点、第 1 列写 '-'
      ],
      "rowGapCells": 1.2
    },
    {
      "mode": "handwritten", "isBossWave": true,
      "rows": [
        { "template": "e_miniboss_blue4|-|e_slime_green|_|e_slime_green" },   // 4 格小BOSS 锚点（占 2 列 × 2 行）
        { "template": "-|-|e_slime_white|_|e_slime_white" }                   // 承接上一行的占位（'-' 由上一行的锚点覆盖）
      ]
    }
  ]
}
```

**随机波（按权重抽）**：

```jsonc
{
  "mode": "random", "seed": 20261003,
  "bands": 3,                    // 生成 3 个带（= 6 行）
  "qualityWeights": [30, 25, 20, 13, 8, 4],
  "typeWeights":    { "normal": 78, "elite": 18, "miniBoss": 3, "boss": 1 },
  "shapeWeights":   { "s1": 6, "h2": 3, "v2": 3, "s4": 1, "s6": 0.5, "s8": 0.3 }
}
```

**行模板语法（`RowDef.template`）** —— 5 个槽位用 `|` 分隔：

| 写法 | 含义 |
|---|---|
| `enemy_def_id` | 该列放这个敌人（**锚点格**） |
| `-` | 该格**被相邻锚点占用**（同一行左侧的横版敌人，或上一行的竖版/大怪），**不是空列** |
| `_` 或留空 | 该列**故意空着**（造型用，子弹可以穿过） |

### 9.7 关卡数据结构

```ts
interface LevelDef {
  id: string;
  name: string;
  seed?: number;                    // 随机生成用；同 seed 可复现
  waves: WaveDef[];
  hpMul?: number;                   // 关卡级难度倍率（覆盖全局曲线）
  speedMul?: number;
  isEndless?: boolean;              // 无尽模式：波次按公式无限生成
}

interface WaveDef {
  mode: 'handwritten' | 'random';
  seed?: number;
  rows?: RowDef[];                  // 手写
  bands?: number;                   // 随机：生成几个带
  qualityWeights?: number[];        // 随机：品质权重（6 项）
  typeWeights?: Record<string, number>;
  shapeWeights?: Record<string, number>;
  rowGapCells?: number;             // 默认 1.2（相邻两行的纵向间距，单位：格）
  spawnStaggerBudget?: number;      // 默认 0.5（带内弹出允许占用一个行间隔的比例）
  spawnStagger?: number;            // 默认 0.08 s
  fallSpeed?: number;               // 覆盖默认下移速度
  isBossWave?: boolean;
}

interface RowDef {
  template: string;                 // "e_slime_white|e_slime_white|-|_|e_slime_green"
}
```

## 10. 开局天赋三选一【需求 3】

### 10.1 流程

```
进入游戏
   ↓
展示 3 个随机天赋（卡面：名称 / 图标 / 描述 / 稀有度）
   ↓
玩家选 1 个 → 天赋立即生效（属性类直接改数值，机制类挂上钩子）
   ↓
游戏开始：第一波敌人开始入场
```

| 规则 | 说明 |
|---|---|
| 候选数量 | **3 个**（可配置 `talentOfferCount`） |
| 是否可跳过 / 重抽 | v1.0 **不可**（保持"开局定调"的仪式感）；后续可用金币重抽（候选池见附录 C） |
| 同一局内 | 开局天赋**只能选一次**，之后通过升级（§11.4）继续成长 |
| 与局外养成的叠加 | 开局天赋叠加在外围加点之上（先算加点，再算天赋） |

### 10.2 天赋 = 技能的一种（配置化要求）

**天赋不是独立的系统**，它是技能表里 `kind = Talent` 的一类：

```ts
enum SkillKind { Talent, Active, Passive }   // 天赋 / 主动 / 被动
```

- 天赋与普通技能**共用同一套数据结构、同一套效果聚合、同一套配置文件**（§12.2、§15）；
- 区别只体现在**获取时机**：`Talent` 只在开局三选一出现，`Active/Passive` 在升级三选一出现；
- 因此"加一个新天赋"= 往技能表加一行 + 出一张图标，**不需要改代码**。

### 10.3 开局天赋池（建议首批 6 个）

| ID | 名称 | 稀有度 | 效果 | 定位 |
|---|---|---|---|---|
| `t_extra_bullet` | **多发弹匣** | 普通 | `bulletCount +2` | 更宽容的弹药 |
| `t_heavy_shot` | **重弹头** | 普通 | `bulletDamage +40%` | 前期清怪更快 |
| `t_fast_hands` | **快枪手** | 稀有 | `fireInterval −20%` | 高频手感 |
| `t_magnet_core` | **磁吸核心** | 普通 | `magnetRadius +50%` | 成长更快（吃经验效率） |
| `t_iron_body` | **铁壁** | 稀有 | `maxHp +30`、`diveDamageMax −20%` | 容错 |
| `t_bounce_master` | **弹射大师** | 史诗 | 子弹撞墙后速度 +15%（可叠 3 次），回收时清零 | 高风险高收益：让子弹"越弹越快" |

- 权重：普通 60 / 稀有 30 / 史诗 10；
- 抽取**不重复**；池子不足 3 个时用普通天赋补位（保底）；
- 全部天赋都必须是**纯数据 + 效果项**，禁止在代码里为某个天赋写专属分支。

## 11. 掉落与成长【需求 4】

### 11.1 掉落触发与散落规则

| 规则 | 内容 |
|---|---|
| **触发** | **每击杀一个敌人**即掉落（不需要"概率掉落经验"） |
| **散落方式** | 以敌人所在位置为**圆心**、半径 **0.2 格 = 16 px**，向**随机方向**散落（原地轻微散开，不做抛物线飞出） |
| **散落动画** | 出现时 0.2 s 的缩放弹出 + 轻微位移，让玩家注意到"这儿掉了东西" |
| **单位说明** | 需求里的"半径 0.2"按**格**理解（1 格 = 80 px → 0.2 格 = 16 px）。这是已拍板结论，不是屏幕比例 |

### 11.2 四类掉落物

| 掉落物 | 外观 | 触发条件 | 数量 | 携带数值 | 用途 |
|---|---|---|---|---|---|
| **经验水晶** | 蓝色菱形 | **每次击杀** | 1 颗（BOSS 按占格数 **2~4 颗**） | `品质经验 × 类型经验倍率` | 累积升级（§11.4） |
| **超级水晶** | 紫色方块 | 精英（**15%**）/ 小BOSS（100%）/ 大BOSS（**2 颗**） | 1 ~ 2 | —— | **升级 / 进化 / 融合**技能（§11.6） |
| **金币** | 金色圆币 | **每次击杀**（按品质给量） | 1 ~ 25（白 1 → 红 25） | —— | **刷新**三选一候选、**购买**技能（§11.7） |
| **魂晶** | 青色六边形 | 精英（1）/ 小BOSS（3）/ 大BOSS（10） | 1 ~ 10 | —— | **外围养成加点**（局外持久，§18） |

**示例**：击杀一个红色大BOSS（8 格）= 经验水晶 4 颗（每颗 `32 × 20 = 640` 经验）+ 超级水晶 2 颗 + 金币 25 + 魂晶 10。

### 11.3 拾取规则（磁吸）

| 规则 | 值 | 说明 |
|---|---|---|
| **自动磁吸** | `magnetRadius` 初始 **1.5 格 = 120 px** | 进入范围后掉落物**自动飞向玩家**，不需要手动点击 |
| **磁吸范围可升级** | 技能 / 外围加点都能提升 | "捡东西的效率"本身是一条成长线 |
| **范围外** | 留在原地不动 | 玩家需要主动走过去 |
| **超时消失** | `dropLifeTime` 默认 **15 s**，最后 3 s 闪烁提示 | 防止场上堆积过多节点 |
| **同屏上限** | 建议 **80 个**，超出时最旧的自动消失 | 微信小游戏性能兜底 |

### 11.4 升级流程

```
经验累积 ≥ 当前等级所需经验
   ↓
暂停战斗（敌人、子弹、特效全停）
   ↓
弹出【3 选 1】面板：
   ├── 学习新技能（从技能池按权重抽取未学过的技能）
   ├── 升级已有技能（给已学技能 +1 级，不超过 maxLevel）
   └── 附加操作：金币刷新候选（§11.7）、金币直接购买技能、超级水晶区（§11.6）
   ↓
玩家选择 → 应用效果 → 关闭面板 → 恢复战斗
```

| 规则 | 说明 |
|---|---|
| 候选数量 | **3 个**（可配置） |
| 候选来源 | 所有**未满级**的技能（已满级的不再占用候选位） |
| 同一次三选一 | **不重复**出现同一技能 |
| 保底 | 若 3 张全是"已有等级 > 0"的技能，**强制替换 1 张**为未学过的技能（避免整局看不到新东西） |
| 稀有度权重 | 普通 60 / 稀有 30 / 史诗 10 / 传说 3（受"高级技能概率"加点影响，§18） |
| 连续升级 | 一次击杀可能同时触发多级 → 候选**排队**，逐个弹出 |
| 死亡时 | **清空待处理的升级队列**（否则升级面板会盖住结算面板，造成软锁） |

### 11.5 经验曲线

**公式**：`need(n) = 8 + 6 × (n−1) + 1.5 × (n−1)²`（`n` = 当前等级，向上取整）

| 等级 n | 升级所需经验 | 累计经验 |
|---|---|---|
| 1 → 2 | **8** | 8 |
| 2 → 3 | **16** | 24 |
| 3 → 4 | **26** | 50 |
| 4 → 5 | **40** | 90 |
| 5 → 6 | **56** | 146 |
| 6 → 7 | **76** | 222 |
| 7 → 8 | **98** | 320 |
| 8 → 9 | **124** | 444 |
| 9 → 10 | **152** | 596 |
| 10 → 11 | **184** | 780 |
| 12 | **256** | 1254 |
| 15 | **386** | 2276 |

> **说明**：本表按公式**重新计算**。旧文档 §26.5 给出的表格与它自己写的公式不一致（旧表 10→11 写 238，公式算是 184），本版以公式为准。
> **调参提示**：想让前 3 级更快（更早给玩家第一次三选一），只需降低常数项 8 → 5；想压后期节奏就调二次项。

**升级与波次的关系**：升级**只**由击杀驱动，因此
`玩家等级 = f(击杀效率 × 敌人经验值)`，而不是 `波数 − 1`。跑得好的玩家在第 5 波可能已经 Lv.6，跑得差的可能只有 Lv.3 —— **这正是我们要的差异**。

### 11.6 超级水晶：三种用途（升级 / 进化 / 融合）

| 用途 | 条件 | 消耗 | 效果 | 是否占用技能位 |
|---|---|---|---|---|
| **升级** | 任意未满级技能 | **1 颗** | 直接 +1 级（绕过经验） | 不变 |
| **进化** | 技能**已满级** | **1 颗** | 变成该技能的**质变形态** | 不变（仍占原位） |
| **融合** | **两个指定技能都满级** | **2 颗** | 合成**全新技能**，**原两个消失** | **净 −1 位**（腾出空间） |

**进化：必须"改行为"，不是"加数值"**

| 原技能（满级） | 进化形态 | 行为改变（质变） |
|---|---|---|
| 连锁闪电 | **雷暴** | 不再依赖命中：**每次开火自动电击最近的敌人** |
| 穿透弹 | **镜面** | 子弹撞墙时**分裂出一颗临时子弹**（存在 3 秒） |
| 磁吸范围 | **黑洞** | 磁吸范围内的掉落物**主动飞向玩家**，且经验 +20% |
| 重炮 | **过载** | 伤害 +100%，但**每发消耗 2 发弹匣耐久**（风险回报） |
| 速射 | **弹幕** | 射速 +100%，但子弹速度 −30%（子弹更慢回来） |
| 强化体质 | **吸血** | 每次回收子弹**回复 1 点血**（超上限转护盾） |

**规则**：每个技能**只有一个**进化形态（1:1，表里配 `evolve.into`）；进化后**不能再进化**；进化**不增加技能位**。

**融合：让玩家能做"减法"**（Roguelike 后期技能位被垃圾技能占满是常见问题，融合是唯一能"清理并升级"的机制）

| 组合（都需满级） | 融合结果 | 效果 |
|---|---|---|
| 连锁闪电 + 穿透弹 | **雷球** | 命中必定连锁，且**连锁闪电也会弹射** |
| 重炮 + 速射 | **弹链** | 弹匣 +50%，回收速度 +30% |
| 磁吸范围 + 贪婪 | **炼金** | 吸附掉落物时 **30% 概率转化为超级水晶** |
| 强化体质 + 磁吸范围 | **吸血领域** | 每次回收子弹回复 1 血，且磁吸范围翻倍 |
| 缓速场 + 冰封 | **绝对零度** | 冻结期间敌人血量上限 −20%（可斩杀） |

**规则**：融合是**无向的**（A+B 与 B+A 相同，用排序后的 pair key 查表 O(1)）；融合后**两个原技能消失**、新技能占 1 位；融合技能**不能再进化、也不能再融合**（终态）；融合技能强度目标 ≈ **2 个满级技能的 1.3 倍**。

### 11.7 金币的用途

| 用途 | 价格 | 说明 |
|---|---|---|
| **刷新候选** | 首次 **20** 金币，每次 +20（20 / 40 / 60 …），**每次升级重置** | 给玩家"我这局想要的方向" |
| **购买技能** | 按稀有度定价（普通 60 / 稀有 120 / 史诗 220 / 传说 400），**随本局进度上浮**（×`1 + 0.05 × 波数`） | 金币的长期出口；也是"打得快 → 买得起 → 更强"的正反馈 |
| **购买超级水晶** | 建议 200 金币起，随进度上浮 | 给"差 1 颗就能进化"的玩家一个出口 |

### 11.8 魂晶的用途

**只用于外围养成**（局外持久）：加点系统（§18）与皮肤召唤（§19）。
本局内**不消耗**魂晶，结算时统一入库——这样玩家不会在"现在变强"和"长期变强"之间被逼着做选择。

## 12. 技能系统（含天赋）【需求 2 / 4】

### 12.1 分类与稀有度

| 维度 | 取值 | 说明 |
|---|---|---|
| **类别** `kind` | `Talent` / `Active` / `Passive` | 天赋只在开局出现；主动技能可能有冷却/触发；被动是常驻加成 |
| **稀有度** `rarity` | 普通 / 稀有 / 史诗 / 传说 | 决定抽取权重与卡面描边；传说卡建议**每局最多出现 3 次** |
| **上限** `maxLevel` | 每个技能独立配置 | 见 §12.5 |

### 12.2 数据结构：技能 = 一组"效果"，不是一个 if 分支

```ts
interface SkillDef {
  id: string;
  name: string; icon: string; desc: string;   // desc 支持按等级动态生成
  kind: SkillKind;                            // Talent / Active / Passive
  rarity: SkillRarity;
  maxLevel: number;
  weight: number;                             // 抽取权重
  effects: EffectEntry[];                     // ★ 数据驱动效果
  tags: string[];                             // 用于融合判定
  evolveInto?: string;              // 满级后进化成的技能 ID
  evolveCost?: number;              // 进化消耗超级水晶数
  fusePartners?: string[];          // 融合组合："对方ID:产物ID:消耗"（无向，需双向登记）
}

interface EffectEntry {
  target: string;          // 'bulletDamage' | 'fireInterval' | 'chainTargets' | 'magnetRadius' | ...
  op: 'add' | 'mul';       // 加法 / 乘法
  perLevel: number;        // 每级增量（mul 用 0.2 表示 +20%）
  base?: number;           // 基础值（技能自带的基础加成，Lv.0 也生效）
  cap?: number;            // 该效果自身的封顶
}
```

**聚合方式**：把所有已学技能的同类效果累加成一个 **`EffectSummary` 扁平结构**，战斗系统每帧只读它一次：

```
EffectSummary = {
  bulletDamage, fireInterval, bulletCountBonus, catchRadiusBonus,
  pierceDuration, homingDeg, chainTargets, chainDamageRatio, wingmanCount,
  magnetRadius, maxHpBonus, enemyFallSpeedScale, ...
}
```

**收益**：加技能 = 往技能表加一行 + 出一张图标；技能之间**自由组合**（穿透 + 弹射 + 制导同时生效），不需要为每种组合写代码。

```
├────────────────────────────────────────┤

│                          [消耗 2 ◆]     │
└────────────────────────────────────────┘
```

| 交互规则 | 说明 |
|---|---|
| 满级卡片 | 压暗 + 禁止点击 |
| 连点上锁 | 面板首次点击后立即上锁，连点两下不会白加两级 |
| 进化/融合栏 | 没有满足条件的组合时**隐藏**（不占视觉噪音） |

### 12.5 上限与平衡约束

| 技能类型 | 上限建议 | 理由 |
|---|---|---|
| 数值类（重炮） | **10 级**（伤害 ×3.0） | 线性技能超过 10 级后每级感知变弱 |
| 目标数类（闪电） | **8 级**（劈 12 个目标） | 12 已是"全屏"，再多无意义 |
| 功能类（穿透 / 分裂 / 冻结） | **2 ~ 3 级** | 功能叠加是非线性的，必须收紧 |
| 保底类（血上限 / 再生 / 护盾） | **5 级** | —— |

**必须守住的两条**：① 任何技能都不得无上限（旧实现里重炮/闪电都是 `Infinity`，活到第 30 波就会出现 ×6.8 的数值崩坏）；② 单局总强度增长钳在 **10 ~ 15 倍**以内。

## 14. 配置化总则与配置文件清单

### 14.1 三条原则（硬要求）

| 原则 | 含义 | 反面案例（禁止） |

```ts

enum EnemyType       { Normal, Elite, MiniBoss, Boss }           // 普通/精英/小BOSS/大BOSS

  visualRadius: number;      // 视觉半径（40）

  bulletDamage: number;      // 10

  kind: DropKind;

  amountMin: number;
  amountMax: number;
  scatterRadius: number;     // 0.2 格 = 16 px
```

## 16. 数值真源规范与加载流程

### 16.1 数值真源规范（从旧实现的坑里来的硬规则）

| 规则 | 说明 |
|---|---|
| **R1 唯一真源** | 同一数值只能存在于配置文件一处；**禁止**在 prefab / 场景节点上再存一份可覆盖的值 |
| **R2 禁止静默覆盖** | 若确实需要面板级配置（如关卡号），只允许"面板自身参数"，**不允许**战斗数值 |
| **R3 启动断言** | 每次开局打印一行 `[Config] 本局生效数值 = {...}`；对关键值做 `console.assert` 校验，出现分歧立刻暴露 |
| **R4 纯函数钳制** | 数值的合法化（clamp）写成**不依赖引擎的纯函数**（`sanitizeTuning()`），可被无头测试直接覆盖 |
| **R5 review 可见** | 数值变更必须体现在 **文本 diff** 上（JSON/TS/Excel），不允许只存在于二进制或 prefab 里 |

> **历史教训（旧 §14.0）**：上一版实现里，`GamePanel` 上有 22 个数值型 `@property`，Cocos 会用**编辑器序列化进 prefab 的值覆盖脚本默认值**，导致 `waveInterval` 代码写 20 s、实际生效 30 s；`enemyFallSpeed` 代码 25、实际 27；`bulletSpeed` 代码 700、实际 900；`fireInterval` 代码 0.5、实际 0.35。结果：**改 `.ts` 游戏毫无变化**，而且 code review 完全看不出来，一切按代码做的平衡推算全部作废。这套机制**不得在新实现里重演**。

### 16.2 加载流程

```
启动
  ↓
读取 Excel 源表（tools/excel-config/*.xlsx）
  ↓ 导出管线：读取 Excel → 生成 .fbs Schema → 构建 .bin（flatc 另外生成 TS 访问器，见 §17.3）
  ↓
游戏运行时加载 Binary 配置（或 TS 数据模块，二选一，见下）
  ↓
注册配置访问器（`ConfigManager.registerAccessor('Enemy', new EnemyConfigAccessor(buffer))`，访问器由 flatc 生成，接线见 §17.3）
  ↓
校验：主键唯一、权重非负、枚举合法、必填字段非空
  ↓ 校验失败 → 记录错误码 + 回退默认配置（不允许崩在战斗里）
战斗系统只通过访问器读取，不直接 import 具体表
```

| 方案 | 适用 | 说明 |
|---|---|---|
| **A. TS 数据模块**（`gameplay/data/*.ts`） | 早期开发、快速迭代 | 直接 `import`，热重载即生效，diff 友好；缺点是策划要改代码文件 |
| **B. Excel → Binary**（现有管线） | 数值规模化之后 | 策划改 Excel 即可；需要走导出流程（§17） |

> **建议**：v1.0 先用 **A**（结构完全按 §15 定义，字段名与 Excel 表头一致），等数值规模稳定后**无缝切到 B** —— 因为两者的字段定义是同一套，切换只影响"数据从哪来"。

### 16.3 校验清单

> 前 4 项**在导出前**由 `tools/excel-config/verify_templates.py` 静态校验（§17.4），不用等运行时才发现；运行时再按本表兜底一遍。

## 17. 配置表模板（Excel）与导出管线

### 17.1 表头约定（与现有导出器一致）

| 行号 | 用途 | 示例 |
|---|---|---|
| **第 1 行** | 字段名 | `id`, `quality`, `hpPerCell` |
| **第 2 行** | 字段类型 | `string`, `enum:EnemyQuality`, `float` |
| **第 3 行** | 注释说明 | 敌人ID / 品质 / 单格血量 |
| **第 4 行起** | 数据行 | `e_slime`, `1`, `20` |

**支持的字段类型**：`int` / `float` / `bool` / `string` / `enum:枚举名` / `array:int` / `array:string`

**填写注意（会导致导出失败，必须遵守）**：

| 注意 | 说明 |
|---|---|
| 数值列必须是**真数字** | `int` / `float` 列写成文本会被类型校验拒绝并**中止整表导出** |
| 数组写成 JSON 字符串 | 例如 `["a:mul:0.2","b:add:1"]` |
| 注释行以 `#` 开头 | 第 1 列以 `#` 开头的行会被跳过，可用于写分区说明 |
| 枚举写**数字** | `enum:DropKind` 填 `0/1/2/3`，含义写在第 3 行注释里 |
| 一个工作表 = 一张表 | 表名会被转成 FlatBuffers 的表名，**请用英文表名**，不要用中文 |
| **表名不要用 camelCase** | 导出器按 `_`/`-`/空格 分词、每段首字母大写其余小写。写 `BossPhase` 会压平成 **`Bossphase`**；正确写法是 **`Boss_Phase`** → 表名 `BossPhase` |

**类型映射（Excel → FlatBuffers，导出器自动生成）**：

| Excel 标注 | FlatBuffers 类型 | 说明 |
|---|---|---|
| `int` | `int32` | |
| `float` | `float32` | |
| `bool` | `bool` | |
| `string` | `string` | |
| `enum:任意名` | **`byte`** | ⚠️ **不会生成 FBS enum 类型**：`enum:A` 与 `enum:B` 出来都是 `byte`。枚举名只是给策划看的标注，数值含义写在注释行，客户端自己映射成 TS 枚举 |
| `array:int` | `[int32]` | |
| `array:string` | `[string]` | |

**每张表生成的结构**（`namespace Config`）：

```fbs
table Enemy { id:string; quality:byte; ... }   // 单条记录（表名 = 工作表名转 PascalCase）
table EnemyList { items:[Enemy]; }             // 记录列表（客户端读的就是这个）
root_type EnemyList;
```

**实测结论（2026-10-03 用真实导出器跑通）**：8 个模板 / 13 张表全部导出成功（0 失败），产出 13 个 `.bin`（另有单表 `.fbs`）；`flatc` 缺失只影响 TypeScript 访问器生成（打印警告并跳过），不影响二进制导出。完整命令、产物位置与客户端接线见 §17.3。

|---|---|---|

**flatc 25.x 的四个坑（导出器已适配，换工具链时注意）**：

| 坑 | 现象 | 处理 |
|---|---|---|
| `///` 注释不能写在行尾 | `error: a documentation comment should be on a line on its own`，整个 schema 编译失败 | 生成器把注释单独成行（顺带让注释进了访问器的 JSDoc） |
| 一个 namespace 的出口文件会被逐文件覆盖 | 13 个 `.fbs` 分开编译，`config.ts` 里只剩最后一张表（实测只剩 `Tuning`/`Wave`） | 编译前把全部表**合并成一个 `config.fbs`** 再交给 flatc |
| 字段名 camelCase 会有告警 | `warning: field names should be lowercase snake_case, got: enemyId` | 只是告警、不阻断；表格与客户端统一用 camelCase，接受这些告警 |
| `enum:名字` 不生成枚举类型 | 一律落成 `byte`（见 §17.1） | 枚举值含义写在注释行，客户端自己映射 |

**客户端接线（还没做，等玩法代码落地）**：生成的访问器 `import * as flatbuffers from 'flatbuffers'`，所以项目要先有运行时依赖：

```bash
npm i flatbuffers          # 在 Cocos 项目根目录
```

用的时候（`EnemyList` 才是 `.bin` 的根）：

```ts
import * as flatbuffers from 'flatbuffers';
import { EnemyList } from './generated/config';

const bytes = await loadBinary('config/roguelike/Enemy');
const list = EnemyList.getRootAsEnemyList(new flatbuffers.ByteBuffer(new Uint8Array(bytes)));
for (let i = 0; i < list.itemsLength(); i++) { /* list.items(i) → 一条敌人配置 */ }
```

> ⚠️ 项目自带的 `assets/scripts/engine/FlatBuffersRuntime.ts` **不能**直接喂给生成的访问器：它只提供文件加载和一个最简 `ByteBuffer`（`bytes/dataView/position`），没有 `readInt32/__offset/__string` 这些读取 API。二者要么合并（让 `FlatBuffersRuntime` 返回官方 `flatbuffers.ByteBuffer`），要么直接改用官方运行时。**这一条必须在写玩法代码前定下来。**

### 17.4 模板的生成与自检（配套脚本）

模板不是手搓的，改了字段定义就重新生成，改完数据就跑一遍自检：

```bash
# ① 按 §15 的 Schema 重新生成 8 个模板（会覆盖同名文件）
python tools/excel-config/build_templates.py

# ② 自检：表头/类型/枚举/引用/权重/行模板 是否合法（0 错误才算过关）
python tools/excel-config/verify_templates.py
```

**`verify_templates.py` 复刻了导出器的读取规则**（三行表头、类型标注、`array` 必须是 JSON 数组字符串），并额外校验表与表之间的一致性：

| 校验项 | 说明 |
|---|---|
| 主键唯一 | 同表内 `id` 不得重复 |
| 枚举范围 | 品质 0~5、类型 0~3、体型 0~5、手段 0~4 … |
| 概率范围 | `chance` 必须在 0~1 |
| 权重数组长度 | `qualityWeights` 6 项、`typeWeights` 4 项、`shapeWeights` 6 项 |
| 引用存在性 | 关卡行模板引用的敌人、技能效果引用的技能、掉落表引用的敌人都必须存在 |
| **行模板占位覆盖** | 按 `colSpan/rowSpan` 展开锚点：被压住的每一格都必须写成 `-`；写 `-` 的格必须有锚点覆盖；锚点不得重叠、不得超出 5 列 |
| 融合双向登记 | A 写了与 B 融合，B 也必须写与 A 融合 |

> 当前状态：**8 个模板、13 张表、0 错误 0 警告**（数据规模见 §24，字段含义见附录 A）。

# 第四部分 · 外围养成系统【需求 二】

> **定位**：跨局持久的成长线，消耗**魂晶**（游戏内掉落，非付费货币）。
> **两条腿**：①加点系统（数值成长）②召唤系统（皮肤外观）。

## 18. 加点系统

### 18.1 节点表

| 节点 | ID | 每级效果 | 上限 | 满级累计收益 | 设计意图 |
|---|---|---|---|---|---|
| **子弹数量** | `m_bullet_count` | `bulletCount +1` | **10** | +10 发 | 直接提升输出上限（§6 弹匣） |
| **攻击力** | `m_damage` | `bulletDamage +5%` | **20** | +100% | 全线增益 |
| **移动速度** | `m_move_speed` | `moveSpeed +3%` | **10** | +30% | 同时提升接弹与走位（走位=接弹，§6.3） |
| **血量** | `m_max_hp` | `maxHp +10` | **20** | +200 | 容错 |
| **高级技能概率** | `m_high_rarity` | 高稀有度技能出现率 **+2%** | **10** | +20% | 见 §18.3 的提醒 |

### 18.2 成本曲线

**公式**：第 `n` 级消耗 `魂晶 = ceil(costBase × n^costPow)`，默认 `costBase = 2`、`costPow = 1.4`

| 等级 | 单级消耗 | 累计 |
|---|---|---|
| 1 | 2 | 2 |
| 2 | 6 | 8 |
| 3 | 10 | 18 |
| 4 | 14 | 32 |
| 5 | 20 | 52 |
| 6 | 25 | 77 |
| 7 | 31 | 108 |
| 8 | 37 | 145 |
| 9 | 44 | 189 |
| 10 | 51 | **240** |
| 15 | 89 | —— |
| 20 | 133 | —— |

**魂晶产出参照**：小BOSS 3 颗 / 大BOSS 10 颗 / 精英 1 颗。若平均每局能击杀 1 个 BOSS + 5 个精英，约 **15 魂晶/局** → 点满一条 10 级节点约需 **16 局**。这是"长期目标"的量级，可按留存数据调整 `costBase`。

### 18.3 关于"高级技能概率"的设计提醒

> ⚠️ 这是**花钱买运气**，容易产生"我加了概率但还是没出好东西"的负反馈。

**推荐做法**：把它做成**保底机制**而不是纯概率 —— 例如"每 5 次三选一必出 1 张稀有以上"，加点降低这个计数（5 → 4 → 3 → …）。玩家的体感从"赌"变成"攒"，可控得多。

### 18.4 数值叠加顺序

```
最终数值 = 基础值(PlayerDef)
         × (1 + 外围加点加成)        ← 局外，永久
         + 开局天赋加成              ← 局内，开局一次性
         → 再经技能 EffectSummary 聚合 ← 局内，随升级成长
         → 最终 clamp 到安全区间
```

- 加点先算：**保证"局外投入"永远有效**，不会被局内随机性抹掉；
- 加成要用 `EffectEntry` 表达（与技能同一模型），**不要**在加点面板里硬编码数值。

### 18.5 加点面板 UI

| 要素 | 规格 |
|---|---|
| 顶部 | 当前魂晶余额 |
| 节点卡 | 图标 + 名称 + 当前等级/上限 + 下一级效果 +「+」按钮 + 消耗 |
| 状态 | 满级显示"已满"；魂晶不足时按钮置灰并提示差值 |
| 长按 | 支持连续加点（有魂晶就一直点，不必逐次确认） |
| 重置 | v1.0 **不提供**免费重置；后续可做"洗点券"（候选，附录 C） |

| 规则 | 建议 |
|---|---|
| 单次消耗 | **30 魂晶** |

### 19.4 属性与合规红线

| 红线 | 说明 |
|---|---|
| 带属性的皮肤**只能用魂晶获取** | 否则就是"付费变强"，需重新评估平衡与合规 |
| 付费内容保持纯外观 | 一旦付费内容带属性，抽卡概率公示、未成年人保护等要求全部升级 |
| 属性加成**必须可配置** | 写进 `skin.xlsx`（`bonusTarget` / `bonusOp` / `bonusValue`），不允许硬编码 |
| 加成幅度要小 | 建议 ≤ 3~5% 量级，避免"皮肤决定强度" |

```

```

| 规则 | 说明 |
|---|---|
| **升级面板与结算面板的层级冲突** | 三选一面板在 `PopUp` 层，**恒在结算浮层之上**。因此死亡时必须**清空待处理升级队列**，否则"重新开始"按钮会被盖住 → 软锁（旧实现踩过） |
| **谁开面板谁负责停** | 暂停/升级期间冻结整场战斗（敌人、子弹、特效全停）；面板关闭时由开面板的一方负责解冻，避免"面板没了游戏还停着" |
| **事件解绑** | 面板在 `OnClose` 必须 `offAllByTarget(this)`，否则重开一局会出现重复监听（数值翻倍类 bug 的常见来源） |
| **异步校验** | 异步加载回调里必须检查节点/组件是否仍有效（面板可能已被关闭） |

| **掉落物** | 出现时缩放弹出 + 常驻轻微呼吸动画；被磁吸时拖出短轨迹 | 让玩家知道"经验在哪、有多少" |
| **弹药告急** | 弹匣空时屏幕底部中间脉冲提示 | 提示玩家"该去接子弹了" |
| **攻击预警** | 瞄准线 / 红色预警块 / 激光红线，全部用 `Graphics` 画（零美术） | §8.2 的生命线 |

## 25. 平衡方法（可复用，不依赖旧结论）

> ⚠️ 旧文档 §14 的全部平衡结论**已作废**：威胁模型从"被动的墙"变成了"会主动攻击的敌人"，而且旧代码已删除。但**判定方法**仍然有效，本节把它固化下来。

### 25.1 核心判定式

```
① 释放速率 R_release (格/秒) = fallSpeed / cellSize × colCount
   （= 每秒有多少格敌人穿过底线）

② 平均每格血量 E[HP/cell] = Σ(品质权重 × 品质单格血量) × 类型血量倍率
                            × 难度血量倍率
   （品质权重按【当前波次实际配置】算，不能用一个全局平均值糊过去）

③ 玩家清格速率 R_clear (格/秒) = DPS / E[HP/cell]
   DPS = bulletDamage / fireInterval × h        （h = 平均每发命中次数）

④ 生存判定：R_clear ≥ 安全系数 × R_release
   安全系数：前期 1.3，后期 1.5（要给玩家犯错与接弹的时间）
```

**`h`（平均每发命中次数）是本作最特殊的变量**：它由**墙的密度**决定 —— 墙越密，子弹在墙里弹射得越频繁，`h` 越高。所以"敌人变多"既是压力也是收益，这是本作最爽的正反馈。经验值：稀疏 `h ≈ 1.0`，密集墙 `h ≈ 1.5 ~ 2.5`。

### 25.2 第 1 波算例（验证开局有余量）

| 项 | 取值 | 说明 |
|---|---|---|
| 品质权重（第 1 波） | 白 60 / 绿 40 | 前期关卡应**手动压低品质**（关卡表可覆盖权重） |
| E[HP/cell] | `0.6×12 + 0.4×20 = 15.2` | 全普通（×1） |
| R_release | `25 / 80 × 5 = 1.56 格/s` | |
| 需要的 R_clear | `1.3 × 1.56 = 2.03 格/s` | 安全系数 1.3 |
| 需要的 DPS | `2.03 × 15.2 ≈ 31` | |
| 实际 DPS | `10 / 0.35 × h = 28.6 × h` | `h = 1.2` → **34.3** ✅ |

**结论**：第 1 波**必须是有余量的**（约 +10%）。旧实现的致命问题是"缺口从第 1 波起就是负的"，玩家只能在整波时间内零浪费输出才能打平 —— 那不是难度，那是设计错误。

### 25.3 第 20 波算例（验证后期需要成长）

| 项 | 取值 |
|---|---|
| 品质权重（第 20 波） | 白 10 / 绿 20 / 蓝 25 / 紫 20 / 金 15 / 红 10 |
| E[HP/cell] | `53.45`（加权血量） |
| 类型倍率 | 精英占比升到 35% → `≈ 1.87` |
| 难度血量倍率 | ×2.5 |
| 合计 E[HP/cell] | `53.45 × 1.87 × 2.5 ≈ 250` |
| R_release | `62.5 / 80 × 5 = 3.91 格/s` |
| 需要的 R_clear / DPS | `1.5 × 3.91 = 5.86 格/s` → **约 1465 DPS** |
| 玩家成长上限估算 | `28.6 × 技能总倍率 × 加点倍率 × h`；`h = 2.0` 时需要技能×加点 ≈ **25 倍** |

**结论**：后期必须依赖**技能构筑**才能打平 —— 这正是 Roguelike 该有的样子（前期靠手感，后期靠构筑）。同时这也给出了技能系统的强度预算：**满构筑总倍率 ≈ 25 倍**，超过就是数值崩坏。

### 25.4 三条设计目标（用于验收回归）

| 指标 | 目标值 |
|---|---|
| 无头回归 100 局的**存活波数中位数** | **8 ~ 14 波** |
| 三条主流构筑路线的"每级等效 DPS"差距 | **≤ 30%** |
| 第 20 波 `R_clear / R_release` | **≥ 1.0**（有清空的可能，而不是必死） |
| 单局时长（中位数） | **6 ~ 10 分钟** |

### 25.5 校准工具：无头回归（**必须做**）

| 层 | 做法 | 覆盖对象 |
|---|---|---|
| **L1 纯逻辑单元** | 数值/技能聚合/装箱算法抽成**不 import 引擎**的纯模块 | 难度曲线、效果聚合、加权抽取、装箱不重叠 |
| **L2 无头战斗** | 提供最小引擎桩件，在 Node 里 `new BattleWorld()` 并手动喂 `update(dt)` | 子弹弹射/回身/回收、免费弹上限、伤害去重、波次排布、墙满排队、越线判定与俯冲结算 |
| **L3 平衡回归** | 固定种子跑 100 局，输出存活波数分布、DPS 曲线、弹匣空置率 | §25.4 的四条指标 |

- **前提**：玩法逻辑必须**不直接依赖引擎**（只依赖 `Node` 的 `position/active/isValid/addChild/destroy`、`Sprite.spriteFrame`、`Graphics` 绘图等少量接口），且 **RNG 可注入**（禁止裸 `Math.random()`）；
- **成本很低**：引擎桩件约 120 行即可覆盖玩法层用到的接口；
- **收益**：没有它，每次调数值都只能靠手动试玩，迭代速度会崩。

## 26. 验收标准

### 26.1 子弹（需求 1）

### D.2 从旧实现里发现的、值得继承的细节规则

| 规则 | 说明 |
|---|---|
| **行入场速度恒定** | 行入场间隔不随难度变化（难度由行数/速度/血量三条线承担），这是一条隐性缓冲 |
| **血量在入场那一刻结算** | 排队等待的行拖到下一波入场时按**新难度**算血量（刻意设计） |
| **新行/新带的出生时刻由"行时钟"决定** | 不看墙顶在哪，只按「已出生内容需下落本带行数」推进时间；因此行距恒定，既不重叠也不会因墙顶堆积而漂移 |
| **升级面板延迟一帧弹出** | 首波是同步发生的，升级面板要等 UI 就绪后再弹（否则面板还没打开就要求玩家选择） |
| **死亡时清空升级队列** | 三选一面板在 `PopUp` 层恒在结算之上，不清空会盖住"重新开始" → 软锁 |

## 附录 E. 术语表

| 术语 | 含义 |
|---|---|
| **格（cell）** | 128 × 128 px 的最小单位；所有体型与散落距离的基准 |
| **带（band）** | 横排预算单位：5 列 × 1~4 行（含 4/6/8 格竖版 BOSS 时加高）；同一只敌人不跨带 |
| **墙 / 敌人墙** | 逐行排列、刚性整体下移的敌人集合 |
| **底线 / 俯冲线** | y = −567（距屏幕底 100 px）；敌人矩形底边越过它即进入判定流程 |
| **判定窗** | 越线后等待的 1 秒（`diveTelegraph`），期间敌人仍可被击杀 |
| **俯冲（dive）** | 敌人放大 → 快速飞向玩家（缩小）→ 抵达后造成伤害并消失 |
| **弹射（bounce）** | 子弹撞墙/撞敌人后的镜面反弹（不消失） |
| **回身（returning）** | 子弹撞到**底墙**后转入的状态：锁定玩家直飞，穿越敌人不结算伤害 |
| **回收（recycle）** | 子弹进入玩家捕捉圈后被移除、返还弹匣 |
| **主动接弹** | 玩家移动与在外的子弹相交，提前回收（无需按键） |
| **armed** | 子弹必须离开过捕捉圈才允许被回收的标志 |
| **免费弹** | 僚机/分裂弹等不占弹匣的子弹，受独立上限约束 |
| **品质（quality）** | 敌人的 6 色档位（白绿蓝紫金红），决定血量/经验/金币/权重 |
| **类型（type）** | 敌人的 4 类行为档位（普通/精英/小BOSS/大BOSS） |
| **体型（shape）** | 敌人的占格形态（1/2横/2竖/4/6/8 格） |
| **停下释放（stopToCast）** | BOSS 攻击时停止下移、放完继续走的行为 |
| **超级水晶** | 局内稀有掉落，用于**升级 / 进化 / 融合**技能 |
| **魂晶** | 局内稀有掉落，**仅**用于外围养成（加点、皮肤），局外持久 |
| **外围养成** | 跨局持久的成长系统：加点系统 + 召唤（皮肤）系统 |
| **效果聚合（EffectSummary）** | 把所有已学技能/加点/皮肤的效果累加成的扁平结构，战斗系统只读它一次 |
| **确定性 RNG** | 可注入的随机源；同一 seed 必须复现同一关卡（每日挑战与回归测试的前提） |

## 附录 J　操作与瞄准（v1.9 定稿）

### J-1 操作方案 A：一根手指只干一件事

按下点到**玩家中心** `(m_PlayerX, m_PlayerY)` 的距离 `d` 决定这根手指干什么，两者**互斥**：

| 条件 | 行为 | 说明 |
|---|---|---|
| `d ≤ playerGrabRadius`（**74 px**） | **移动玩家** | 沿用相对跟随手感：按下瞬间记 `offset = 玩家位置 − 按下点`，移动时 `clampPlayerPosition(触摸点 + offset)`，点哪里都不会瞬移；**按在玩家身上不改变瞄准方向** |
| `d > playerGrabRadius` | **瞄准** | **立即**把瞄准点设为按下点（点一下即调方向），继续拖动持续调整；瞄准点经 `clampCursorPosition` 夹进屏幕内 |

- `playerGrabRadius` = **74 px** = 1.25 × 玩家球显示半径（`player_001` 80×76 按 contain 适配到一格后显示半径 ≈ 58.9 px）≈ 74 px；比 `playerHitRadius`（45 px）宽松，是为了「按住球一定拖得动」，而不是「必须精确按在判定圆里」；
- **两个触摸用独立 id**（`m_PlayerTouchId` / `m_AimTouchId`），可**同时生效**：一手按住玩家走位、另一手在**任意处**调角度；`TOUCH_MOVE` / `TOUCH_END` / `TOUCH_CANCEL` 各自**只处理自己的 id**；
- 某个角色已被同类手指占用时**忽略**这根新手指（不降级成另一种操作）——否则「已经有一根手指在走位、第二根手指按在玩家身上」会变成改瞄准方向，违反「按在玩家身上不改变瞄准方向」；
- 子弹方向仍由 `m_CursorX / m_CursorY` 决定（`aimVelocity(玩家 → 瞄准点)`），所以这条改动不碰开火逻辑。

### J-2 瞄准浮标：纯方向标识，不可拖动

- 浮标仍是**玩家子节点**、仍贴在**外围圆**上（方向 = 玩家 → 瞄准点，半径 = 玩家图显示半径 + `cursorOrbitGap`），玩家贴近屏幕边缘时用 `CURSOR_FLOAT_EDGE_MARGIN`（48 px）把浮标压回屏内，保证随时可见；
- **抓取判定全部删除**：`isPressOnCursor()`、`CURSOR_GRAB_BAND`（以及旧版文档提到过的 `CURSOR_GRAB_ANGLE`）—— 「按在哪里」不再承担「判断按到了什么」的职责；
- 浮标每帧跟随（`syncCursorNode()`），**自动瞄准时同样更新**；层级不变（敌人 < 玩家 < 浮标）。

### J-3 兜底自动瞄准

| 项 | 规则 |
|---|---|
| 触发 | **瞄准触摸**空闲累计到 `autoAimDelay`（**2.0 s**）后，**每帧**自动瞄准；`autoAimDelay <= 0` 关闭该功能 |
| 目标 | `pickAutoAimTarget(playerX, playerY, enemies)` = **最近的可命中敌人**（用 `isHittable()` 过滤：出生动画中 / 已死的不参与），core 纯函数、可单测 |
| 没有目标 | **保持上一次瞄准方向**（不清零、不重置、不改朝向） |

### J-4 瞄准辅助射线 + 首段反弹射线（**遇墙与遇敌都会反射**）

| 项 | 规则 |
|---|---|
| 主射线 | 从**玩家中心**沿**当前瞄准方向**画一条细线，直到与**最近的墙或敌人**相交 |
| 首段反弹射线 | 在第一次相交点按**真实反射方向**续画第二段：到「第二次相交」或到 `aimGuideBounceLength`（**900 px**），**取其短者**。第一次相交点**可能是墙、也可能是敌人** |
| 与真实弹道一致 | 边界与反射**复用仿真那一套**，不另写近似：`BoardMath.screenBounds()` 取边界、`BulletSim.reflectOffWalls()` 做顶/左/右墙镜面反射（`stepBullet` 也调它）、`BulletSim.hitsBottomWall()` 判底墙；相交半径 = `GameTuning.bulletRadius`；**敌人判定框 = `EnemySim.enemyBox()`（占格 `cols × rows` 与中心点）沿 x / y 两轴外扩 `bulletRadius`** —— 真实子弹 `BoardMath.circleBoxHit()` / `circleHitsBox()` 用的就是这个矩形（矩形两轴各外扩半径，**不是**圆角矩形），**不是另写一套近似**；敌人速度翻转 = `BulletSim.reflectOffEnemyBox()`（`applyBounce` 用的同一个公式）→ 射线顶点与真实子弹的反弹点落在**同一几何位置** |
| 底墙 | **不反射**：真实子弹撞底墙转入「回身」直飞玩家（§6.3 铁律 2），所以射线画到底墙为止（与真实子弹在**同一位置**收尾） |
| 遇敌反射 | 真实子弹撞敌人本来就**只反弹、不消失、不被吃掉**（§6.3 铁律 1：`BulletSim.resolveEnemyHits()` → `applyBounce()`），所以射线**必须**跟着反射 —— 这是让射线「说真话」，**不是**玩法改动。过滤规则与交给子弹的那份列表完全一致：`isHittable()`（出生动画中 / 已死的不挡弹）。命中面反射规则：**左 / 右面翻 `vx`，上 / 下面翻 `vy`**（入射角 = 反射角） |
| 求交顺序 | **所有墙 + 所有可命中敌人**一起比距离，取**最近**的那个交点：命中敌人则该段在敌人处结束并按命中面反射，命中墙则按墙规则。两者**完全重合时按墙处理**（真实仿真每个子步都是「先判墙、再判敌人」，此处同序） |
| 表现 | 细线 `aimGuideWidth` = **6 px**；半透明白 `aimGuideAlpha` = **130**，反弹段更淡 `aimGuideBounceAlpha` = **80**；总开关 `aimGuideEnabled`。**遇敌反射与遇墙反射画在同一条折线上、同一套线宽与透明度**（不额外配色） |
| 层级 | 两个绘制层（`AimRay` / `AimBounceRay`）在 `m_FieldRoot` 下**最早**创建 → 渲染顺序 = **背景 < 射线 < 敌人 < 子弹/掉落/飘字**，即**在敌人之下、背景之上**，不遮挡敌人与飘字 |
| 更新 | 每帧在 `updateAim()` 里跟随瞄准方向重画（**自动瞄准时也更新**），且放在敌人更新之后 → 用的是当帧最新的敌人位置；`traceAimGuide` 内部**不缓存**敌人，敌人一动射线下帧就跟着动 |
| 退化方向 | 瞄准点与玩家重合时不画线（与 `aimVelocity` 的退化兜底「朝正上方」保持一致的处理口径） |
| 退化：起点已在敌人判定框内 | 敌人压到玩家身上时，起点已落在判定框内：立刻按 `circleBoxHit()` 的**最浅穿透轴**反射（与真实子弹第一子步同一套判定），不生成零长线段；已沿法线朝外飞的不再重复反射（真实子弹此刻已被 `applyBounce` 推出表面外） |

**怎么验证与真实弹道一致**（L1 单测 `tests/ball-roguelike/AimGuide.test.ts`）：把**真实子弹**用极细步长（每步 0.144 px，远小于 `maxSubStepDistance`，子步数恒为 1）跑过第一 / 第二次相交，再把两次**翻转位置**与 `traceAimGuide` 的顶点**逐点比对**（撞墙容差 0.25 px；**撞敌人**时法线方向放宽到 0.7 px —— `applyBounce` 会把子弹沿法线推出表面外 `深度 + 0.5` px，而射线顶点严格落在接触面上，切向仍用 0.25 px 同一把尺子），同时比对反射后的方向分量；另外单独覆盖：左 / 右 / 顶墙「入射角 = 反射角」、**敌人左 / 右 / 上 / 下四面与斜射的遇敌反射**、撞角落时两轴同时翻转、**多敌人取最近**、**敌人在墙之后仍按墙反射**、**不可命中敌人被忽略**、**敌人在 `aimGuideBounceLength` 截断之外被忽略**、**起点落在敌人判定框内的退化输入**、底墙在**同一位置**收尾、反弹段被 `aimGuideBounceLength` 截断。

### J-7 遇敌反射（v1.9 补丁）：为什么**不是**玩法改动

| 问题 | 结论 |
|---|---|
| 真实子弹撞到敌人会怎样？ | **反弹**（不是消失、不是穿透、不是被吃掉）。`BulletSim.stepBullet()` 的子步里，先判底墙与顶/左/右墙，再 `resolveEnemyHits()`：对每个接触到的敌人调 `BoardMath.circleBoxHit()` 取**最浅穿透轴**，由 `applyBounce()` 翻转该轴速度分量并把子弹推出表面 —— 与 §6.3 铁律 1「撞敌人、撞墙都只反弹不消失」一致 |
| 那本轮改了什么？ | **只改射线**：把敌人纳入 `traceAimGuide()` 的求交范围（与墙一起取最近交点），遇敌按命中面反射。**子弹、伤害、数值、掉落一律未动**，因此**不是玩法改动**、不影响平衡 |
| 判定形状怎么保证一致？ | 射线直接用 `EnemySim.enemyBox(enemy)`（= `BoardMath.boxFromCells(x, y, cols, rows)`，多格占位的 `boxW/boxH` 与中心点都出自这里）并按 `bulletRadius` 两轴外扩 —— 与真实子弹 `circleBoxHit()` / `circleHitsBox()` 的判定区域是**同一个矩形**；速度翻转用 `BulletSim.reflectOffEnemyBox()`（`applyBounce()` 里的同一个公式） |
| 敌人被击杀 / 还没出生会挡弹吗？ | **不会**。过滤用 `isHittable()`，与 `BattleView.queryHittableEnemies()` 交给子弹的那份列表完全一致（出生动画中与已死的不参与碰撞） |
| 敌人会动，射线会过期吗？ | **不会**。`traceAimGuide()` 是纯函数、内部不缓存敌人；`BattleView.update()` 的顺序是 `updateEnemies()` → `updateAim()` → `drawAimGuide()`，每帧都用当帧最新位置重算 |
| 以后若把子弹改成「撞敌人消失」 | 射线会立刻变成谎话（画出子弹不会走的折线）。届时必须：① 在 `GameTuning` 加开关（如 `bulletBounceOnEnemy`），② 让射线与子弹**共用**同一开关与同一判定，③ 在本附录把它标注为**玩法改动** |
