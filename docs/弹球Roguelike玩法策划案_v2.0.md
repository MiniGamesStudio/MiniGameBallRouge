## 0. 文档说明

### 0.1 一句话玩法

> 你控制一个只能靠**接住自己打出的弹球**来续弹的球手：瞄准后自动开火，弹球在屏幕四壁与敌人之间弹射，撞到底部后回身；你一边走位躲俯冲，一边主动迎向回身的弹球把它收回弹匣，在 8 波滚动关卡里靠三选一不断变强。

## 1. 玩法总览

### 1.1 定位

- **品类**：竖屏、单指/双指、弹球 + Roguelite 构筑。
- **单局目标时长**：一关 8 波，设计目标 **4~6 分钟**；当前排期估算约 **3.6 分钟**（不含清场），偏短（§12.4）。
- **目标用户**：微信小游戏泛用户；前 30 秒必须能"看懂、打中、捡到"。
- **差异化**：不是"自动射击躲弹幕"，而是"**射击—回收**"的节奏管理。玩家的核心操作不是点开火，而是**决定站在哪、什么时候迎向回身的球**。

### 1.2 核心循环

```
          ┌──────────────────────────────────────────────┐
          │  瞄准（手指在玩家外） → 自动开火（0.35s/发）  │
          └───────────────────┬──────────────────────────┘
                              ↓
        弹球在顶/左/右墙与敌人之间弹射，造成伤害
                              ↓
        撞到底墙 / 8s 超时 → 回身，朝玩家飞回（穿透敌人）
                              ↓
        玩家移动接球 → 弹匣 +1 → 可以继续射
                              ↓
        击杀 → 经验 / 金币 / 魂晶 / 超级水晶 → 升级
                              ↓
        升级 / 开局 → 三选一 → 数值或机制变强
                              ↓
        更高波次 → 更多敌人 / 更高血量 / 更快滚动 / 更频繁俯冲
                              ↓
              死亡 → 结算（魂晶） → 外围加点 / 皮肤 → 下一局
              过关 → 下一关（当前有 bug，见 §5.5）
```

### 1.3 三条设计支柱

| 支柱 | 要解决的问题 | 对应系统 | 验收信号 |
|---|---|---|---|
| **接弹节奏** | 玩家为什么不停下来？ | 弹匣、回身、接弹半径、瞄准 | 一局内主动接弹次数 ≥ 击杀数 × 0.8；空弹匣时长占比 < 25% |
| **读屏与走位** | 玩家为什么死？ | 俯冲预警、冻结/灼烧、伤害飘字 | 80% 的受伤发生在"看得到预警之后"；盲区死亡 < 10% |
| **构筑差异** | 第二局为什么不一样？ | 开局天赋、技能池、特殊弹 | 两局的首选三张卡重合度 < 50%；存在至少 3 种可行流派 |

### 1.4 一局流程（当前实现）

| 阶段 | 触发 | 表现 | 是否暂停世界 |
|---|---|---|---|
| 进入 | `GamePanel` 挂载 `BattleView` | 加载美术、建玩家与浮标、HUD | — |
| 开局天赋 | `showTalentChoice()` | 三选一卡片，从技能池抽 3 | ✅ 暂停 |
| 第 1 波 | 选完天赋 | **整波方阵（≥4 行）在 t=0 一次性出生**，0.25 s 缩放后一起下落（v1.14） | — |
| 开火解锁 | 场上出现第一只可命中敌人 | 之前完全不射，也不推进特殊弹 CD | — |
| 升级 | 经验达到 `expNeed(level)` | 三选一；可连升，逐层弹 | ✅ 暂停 |
| 换波 | 本波最后一个敌人出生后满 8 s | 下一波开始；**不等清场** | — |
| 第 8 波清空 | `m_Wave >= 8` 且 `m_Enemies` 为空 | `finishLevel()` → "下一关 / 返回主页" | ✅ 暂停 |
| 死亡 | 玩家 HP ≤ 0 | `finishGameOver()` → "重新开始 / 返回主页" | ✅ 暂停 |

> **实现细节**：世界暂停时，`update()` 仍在跑，只是 `scrollDelta = 0`；因此**状态效果计时、俯冲、磁吸、特殊弹 CD 都照常**。这是刻意设计（否则冰冻会把自己永久冻住），但也导致"暂停时怪还在俯冲"的观感问题。

### 1.5 操作方案 A（当前唯一方案）

| 手指位置 | 行为 | 细节 |
|---|---|---|
| 按下点距玩家中心 ≤ **74 px** | **移动玩家** | 相对跟随：`offset = 玩家 − 按下点`，移动时 `玩家 = 触点 + offset`，不会瞬移 |
| 其他位置 | **瞄准** | 按下即把瞄准点设为触点；可拖动持续调整；抬手后方向保持 |
| 第二根手指 | 独立 | 移动手指与瞄准手指用不同 touch id，互不抢占 |
| 同类手指已占用 | 忽略 | 例如已在走位时，第二根手指再按玩家身上不会改成瞄准 |

- **没有开火键**：开火全自动，方向 = 玩家中心 → 瞄准点。
- 浮标只是方向指示，不能拖；它始终在玩家周围固定轨道上（§3.2）。
- 自动瞄准：**2 s** 没有瞄准触摸后，自动锁最近的敌人；一旦再次触摸瞄准，立刻交还控制。

## 2. 子弹系统

### 2.1 三条铁律

当前 `core/BulletSim.ts` 用三条不可破坏的规则定义手感：

1. **子弹只有一条消失路径：被玩家接住。** 不会撞敌人消失、不会飞出屏幕、不会因波次结束清场。
2. **只有底墙会让子弹回身。** 顶 / 左 / 右墙是镜面反射，底墙不反弹，命中即转入 `Returning`。
3. **回身中的子弹穿透敌人，不造成伤害，也不被敌人弹开。** 它只存在一个目标：玩家。

> 这三条决定了"弹匣永远不会真正打空，只会暂时不在手上"——玩家不会因为没子弹而停火，只会因为**没接住**而停火。这是本玩法与普通自动射击的根本区别。

### 2.2 弹匣与发射

| 参数 | 当前值 | 说明 |
|---|---|---|
| 初始弹数 `bulletCount` | **5** | 场上未回收的弹匣弹上限 |
| 开火间隔 `fireInterval` | **0.35 s** | 每发之间的最小间隔 |
| 弹速 `bulletSpeed` | **1440 px/s** | 60 fps 下 24 px/帧 |
| 单发伤害 `bulletDamage` | **10** | 可被技能加到 25 |
| 子弹半径 `bulletRadius` | **16 px** | 同时用于碰撞与辅助线 |
| 接弹半径 | **61 px** | `45 + 16 + 技能加成`，不是独立常量 |
| 最长存活 `maxBulletLife` | **8 s** | 超时强制回身 |
| 回身速度 | `bullet.speed × 1.0` | 与出膛同速；特殊弹吃自己的 `speedMul` |
| 单帧子步距离 | **13 px** | 每帧最多 16 子步 |

**账本语义**：

- `m_MagazineOut` = **场上还没回收的弹匣弹数量**，不是"已消耗"。
- 可发数 `free = bulletCount − m_MagazineOut`；`free ≤ 0` 时停火。
- 弹匣容量提升（**v1.15 起只来自外围养成**）在"弹全在外"时会让 `free` 立即变大（不返还、不补弹）；场上弹数上限恒 ≤ `bulletCount`。
- 空弹匣期间 `m_FireTimer` **继续累加且不清零**；一旦接回，下一帧若已超过间隔就立即出膛。

**开火闸门**：场上出现第一只 `isHittable` 敌人前，`m_FireUnlocked = false`，不射、也不推进特殊弹 CD。这样开局加载/过场不会空转。

**每帧顺序**（`BattleView.update`）：

```
updateFiring() → updateSpawning() → updateStatuses() → updateScroll()
→ updateEnemies() → updateBackground() → updateDrops() → updateAim()
→ updateFeedback() → updateBullets() → updateSpecialBullets()
→ updateChainFx() → updateWaveFlow() → updateHud()
```

> 因为 `updateFiring` 在 `updateBullets` **之前**，弹匣弹本帧被接回后，**最早下一帧**才能再射；特殊弹在 `updateSpecialBullets` 内，**同一帧**就能补射。这个不对称是"特殊弹更顺滑"的隐藏原因之一。

### 2.3 弹射规则

| 碰撞对象 | 结果 | 细节 |
|---|---|---|
| 顶 / 左 / 右墙 | **镜面反射** | 只翻转对应轴分量，速率不变 |
| 底墙 | **不反射，回身** | 判据 `y − radius ≤ bottom`；位置夹到 `bottom + radius` |
| 敌人 | **反射 + 伤害** | 按圆形与矩形**最浅穿透轴**翻转；沿法线推出 `depth + 0.5 px` |
| 多个敌人同时接触 | **全部吃伤害**，只按最浅的那个弹开 | 一次接触窗口内每个敌人最多一次 |
| 玩家 | **只回收，不反弹** | 仅 `armed == true` 时 |

- 子弹在墙/敌反射中**不损失速率**；只有回身时重设为 `speed × returnSpeedScale`。
- 敌人是"实心矩形"：即使视觉是圆形怪物，碰撞也按 `cols × cell × rows × cell` 的盒子算。
- 一次穿透 2 格 / 4 格敌人，**只结算一次**，不是每格一次。

### 2.4 回身、回收与接弹

**回身两条路径**：

1. 撞到底墙（主要路径）；
2. `life ≥ 8 s`（兜底，只在 `Flying` 状态每帧检查一次）。

**回身时**：

- 状态置 `Returning`；
- **强制 `armed = true`**（覆盖"在捕捉圈内撞底墙"的死循环）；
- 清空 `hitSet`；
- 朝玩家重新定向；
- 之后**每个子步都重新锁定玩家**，所以玩家跑动时子弹会拐弯追。

**接弹**：

- 判据：任意 `armed` 子弹（含 `Flying` 与 `Returning`）与玩家中心距离 ≤ `catchRadius`，在**每个子步末**检测。
- 接弹位置就是回收位置；子弹节点立即销毁。
- 没有额外按键、没有判定窗口；**移动身体撞上去**即可。

**出膛保护**：

- 新弹 `armed = false`；只有离玩家 **> catchRadius** 后才置 `true`。
- 因此刚出膛的子弹不会被自己瞬间收回；而回身时强制 `armed`，保证"子弹回到身边一定能接"。

### 2.5 命中与去重

- 每颗子弹带 `hitSet: Set<enemyId>`。
- **一次接触窗口内**，同一敌人只结算一次；离开后再撞可以再次结算。
- 窗口结束判据：每帧末尾用 `queryEnemies(x, y, radius + 1)` 取"仍接触集合"，不在集合内的 id 被移除。
- **只在帧末剪枝一次**，帧内不剪枝；因此"同一帧内连续两次撞同一敌人"不会重复扣血。
- 一次穿透多格敌人只扣一次，这是"大怪不会被一发子弹打成筛子"的关键。

### 2.6 特殊子弹（v1.12 新增）

#### 2.6.1 共同规则

| 规则 | 当前实现 |
|---|---|
| 种类 | 闪电 `Lightning`、火球 `Fire`、冰冻 `Ice` |
| 获取 | 技能 `s_lightning` / `s_fireball` / `s_ice`，等级 1-5 |
| 并发 | **每种同时只有 1 发在飞** |
| 弹匣 | **不占**弹匣、不占免费弹 |
| 物理 | 与弹匣弹完全一致：反弹、回身、8 s 兜底、同一接弹半径 |
| 回程速度 | 吃自己的 `speedMul`（闪电 1.6×、火球 1.1×、冰冻 1.2×） |
| CD | **飞行中照常倒计时**；回收时若 CD 已好，**同一帧**可再射 |
| 发射 | 自动，不需要玩家额外操作；与弹匣共用开火闸门 |
| 等级 | `specialBulletMaxLevel = 5`；`level = 0` 表示未学 |

**CD 状态机**：

```
stepSpecial(dt): cooldown = max(0, cooldown - dt)   // 不看 inFlight
readyToFire = level > 0 && !inFlight && cooldown <= 0
markFired: cooldown = CD; inFlight = true
markCaught: inFlight = false                        // 不重置 CD
```

- `markCaught` 幂等；`removeBullets` 对非弹匣弹再调一次，防止永久卡 `inFlight`。
- **三种特殊弹可以同帧齐射**：学技能时新建状态 `cooldown = 0`，下一次同步等级后立即满足 `readyToFire`；没有错峰、没有首发延迟。
- **CD 下限在 5 级内永远不会生效**：闪电要 L6+、火球 L8+、冰冻 L7+ 才触及下限。三个 `*MinCd` 目前是**死按键**。

#### 2.6.2 数值表

**闪电（Lightning）**

| 级 | CD (s) | 本体伤害 | 连锁目标数（含锚点） | 单跳连锁伤害 | 弹速 (px/s) |
|---|---|---|---|---|---|
| 1 | 3.00 | 14 | 3 | 10 | 2304 |
| 2 | 2.64 | 21 | 4 | 15 | 2304 |
| 3 | 2.32 | 28 | 5 | 20 | 2304 |

| 5 | 1.80 | 42 | 7 | 30 | 2304 |

- 1 级满命中总伤 = `14 + 2×10 = 34`；5 级 = `42 + 6×30 = 222`。
- 连锁**无衰减**：每跳都是完整的 `chainDamage`。
- 锚点**不吃**连锁伤害，只吃本体那一下。
- 同一条链内不重复；不同次命中可以再次选中同一敌人。
- 目标选择：从锚点开始**逐跳贪心取最近**，距离相同按 id 升序。

**火球（Fire）**

| 级 | CD (s) | 本体伤害 | 灼烧时长 (s) | 每跳伤害 | 跳数 | 灼烧总伤 | 弹速 |
|---|---|---|---|---|---|---|---|
| 1 | 2.50 | 16 | 3.0 | 8 | 6 | 48 | 1584 |
| 2 | 2.25 | 24 | 3.4 | 12 | 6 | 72 | 1584 |
| 3 | 2.03 | 32 | 3.8 | 16 | 7 | 112 | 1584 |

| 5 | 1.64 | 48 | 4.6 | 24 | 9 | 216 | 1584 |

**冰冻（Ice）**

| 级 | CD (s) | 本体伤害 | 冻结时长 (s) | 弹速 |
|---|---|---|---|---|
| 1 | 4.00 | 10 | 1.20 | 1728 |
| 2 | 3.60 | 14 | 1.45 | 1728 |

| 4 | 2.92 | 22 | 1.95 | 1728 |

- 冻结覆盖率：1 级 **30%**，5 级 **84%**（2.20 / 2.62）。

#### 2.6.3 强度折算与风险

按"每次命中都打满、CD 一到就射"折算：

| 特殊弹 | Lv1 单次总伤 | Lv1 折算 DPS | Lv5 单次总伤 | Lv5 CD | Lv5 折算 DPS | 说明 |
|---|---|---|---|---|---|---|
| 闪电 | 34 | 11.3 | 222 | 1.80 | **123** | 需要 7 个目标才打满 |
| 火球 | 64 | 25.6 | 264 | 1.64 | **161** | 单体满跳，最稳定 |
| 冰冻 | 10 | 2.5 | 26 | 2.62 | **9.9** | 价值在 84% 全场时停 |
| 弹匣弹 | — | **31** | — | — | — | 单目标、计暴击期望 |

结论：

- **满级火球 / 闪电的免费 DPS 是弹匣弹的 4~5 倍**，且不需要瞄准、不占弹匣、不需要接弹。
- 冰冻满级把全场时停覆盖率推到 **84%**；由于子弹在冻结期间照常飞、CD 照常走，实际覆盖率更高。玩家可以靠"冰冻 + 自动瞄准"把游戏变成看动画。
- 三种特殊弹同帧齐射，会让爆发伤害在同一帧堆叠，进一步削弱"接弹节奏"。
- 这不是"特殊弹太强"这么简单，而是**它们绕开了玩法唯一的核心资源（弹匣）**。

### 2.9 设计意图与优化方向

**保留**：

- 三条铁律不变；这是玩法身份。
- 底墙回身、回身穿透、主动接弹不变。
- 8 s 兜底保留，防止子弹永久丢失。

**要改**（详见 §13）：

1. **给特殊弹加"参与成本"**：要么占 1 个弹匣位，要么需要命中/接弹充能，要么必须手动激活；不能继续做"免费自动 DPS"。
2. **错峰发射**：三种特殊弹不能同帧齐射；至少加 0.15~0.3 s 的首发延迟或共享 0.5 s 的公共 CD。
3. **冰冻改为局部或降覆盖率**：目标覆盖率 ≤ 50%；或者冻结只停敌人，不停世界；或者满级时长 ≤ CD × 0.5。
4. **清理死键**：`catchRadius` 常量、`freeBulletMax`、三个 `*MinCd` 要么接入，要么删除；不要留在真源里误导策划。
5. **对象池**：子弹 / 飘字 / 掉落 / 敌人节点全部 create-destroy，8 波重叠时会明显抖动；至少先池化子弹与飘字。

## 3. 瞄准与输入

### 3.1 操作方案 A 的判定细节

| 项 | 值 | 说明 |
|---|---|---|
| 抓玩家半径 | **74 px** | 按下点落在玩家中心 74 px 内 = 走位 |
| 瞄准点夹取半径 | **45 px** | 瞄准点不能进入玩家 45 px 内，避免零向量 |
| 浮标贴边余量 | **48 px** | 玩家贴边时浮标压回屏内 |
| 自动瞄准延迟 | **2.0 s** | 只被"瞄准触摸"清零，走位不清零 |
| 开火 | 全自动 | 没有开火键，方向 = 玩家 → 瞄准点 |

- 走位是**相对跟随**：按下时记录 `offset = 玩家 − 触点`，之后 `玩家 = 触点 + offset`；所以点玩家边缘不会瞬移。
- 两根手指用独立 id；同类手指已占用时新手指被忽略，不会降级成另一种操作。
- 瞄准支持"点一下"和"按住拖"；抬手后方向保持，不会回弹到正上方。

### 3.2 浮标

| 项 | 当前值 | 说明 |
|---|---|---|
| 轨道半径 | `max(玩家图宽, 高)/2 + 50` ≈ **108.9 px** | 玩家图 80×76，contain 后显示 117.8×111.9 |
| 显示尺寸 | **50 × 65 px** | 字面量；美术原图 40×56 |
| 位置 | 玩家中心 + 单位方向 × 轨道半径 | 方向用**未夹取**的瞄准方向 |
| 贴边 | 浮标位置压回屏内 48 px | 朝向仍按真实方向，所以贴边时浮标"偏"但箭头仍指对 |
| 层级 | 玩家子节点，玩家每帧被提到最上层 | 浮标永远盖在敌人 / 子弹之上 |

> 浮标是**方向指示器**，不是摇杆：它不能被拖动，也不会跟随手指位置。玩家实际瞄准的是"手指按下的地方"，浮标只是把方向可视化。

### 3.3 辅助射线

| 项 | 当前值 |
|---|---|
| 总开关 | 开 |
| 反射次数 | **1 次**（主射线 + 第一段反弹） |
| 线宽 | **8 px** |
| 虚线 | 段长 **18 px** / 间隔 **12 px** |
| 描边 | 单边 **2 px**，颜色**白色**，alpha 150 |
| 主射线 alpha | **130** |
| 反弹段 alpha | **80** |
| 反弹段长度上限 | **900 px**（与第二次相交取短者） |
| 求交半径 | **16 px**（与真实子弹一致） |

- 主射线从玩家中心出发，取"四面墙 + 所有可命中敌人"的最近交点；**主段不受 900 px 限制**。
- 遇敌会按命中面法线反射；与墙重合时按墙处理。
- **底墙不反射**：射线到该点即止。
- 反弹段只画第一段，长度取 `min(交点距离, 900)`；用尽即停。
- 每帧用当帧敌人重算，**无缓存**；敌人多时是纯 CPU 开销。

> 辅助线与真实子弹共用 `reflectOffWalls()` 和 `circleBoxHit()`，单测要求逐点重合（墙容差 0.25 px、敌人法向 0.7 px）。这是"看得准 = 打得到"的基础，不能为了性能改成近似算法。

### 3.4 自动瞄准

- 触发：连续 **2.0 s** 没有瞄准触摸。
- 目标：距离玩家中心最近的 `isHittable && hp > 0` 敌人；**中心距**，不做到矩形最近点投影。
- 行为：每帧把瞄准点设为该敌人中心，再做 45 px 夹取；**不做目标粘滞**，敌人死了立刻换下一个。
- 无敌人：保持上一次方向。
- 打断：任意瞄准触摸立刻清零空闲计时，交还控制。
- **走位不清零**：你可以一边走位一边让自动瞄准继续工作。

## 4. 敌人

### 4.1 三轴模型

敌人 = **品质（数值档）× 类型（行为/奖励档）× 体型（占格/血量/伤害档）**。

| 轴 | 枚举 | 作用 | 是否可配置 |
|---|---|---|---|
| 品质 | 白 / 绿 / 蓝 / 紫 / 金 / 红 | 每格血量、经验、金币、生成权重 | 🟡 权重在代码；表里有模板 |
| 类型 | 普通 / 精英 / 小BOSS / 大BOSS | 血量倍率、经验倍率、魂晶/超级水晶、金币加成 | 🟡 倍率在代码；组合硬编码 |

### 4.5 数值公式

```
enemyMaxHp   = max(1, round(hpPerCell[quality] × cells × typeHpMul[type] × hpMul(wave)))
enemyExp     = max(1, round(qualityExp[quality] × typeExpMul[type]))      // 与格数无关
enemyCoin    = round(qualityCoin[quality] × max(1, typeExpMul[type] × 0.5))
diveDamage   = min(5 × cells, 40)
```

- 血量随占格数线性增长；经验**不随格数增长**。所以"打大怪"经验效率低，只有掉落与击杀价值。
- 4/6/8 格 BOSS 的经验只按 1 个敌人的品质算，不按格数乘。
- 大怪品质下限蓝，所以 4 格小BOSS 最低 840 血（蓝 35 × 4 × 6）。

### 4.6 生成与排布

**当前只支持随机生成**，没有手写关卡运行时代码。

#### 4.6.1 波次计划

```
targetRows = min(4 + 0.6 × (wave − 1), 12)      // v1.15：3 + 0.5 → 4 + 0.6
while totalRows < targetRows:
    决定这一带是"大怪带"还是"单行带"
    大怪带：选 4/6/8 格（权重 5/3/2），大怪固定占第 1、2 列；
            其余格子按 12% 留空、15% 精英补 1 格怪
    单行带：5 列逐列填；35% 放 2 格横，12% 留空，否则 1 格；
            15% 精英
    totalRows += 本带行数
```

- 行数目标可以是小数；按带累加会**溢出**：第 2 波 4.6 → 实际 5 行；第 8 波 8.2 → 实际 9 行。
- 大怪带出现条件：
  - 最后一波第 0 带**必出**；
  - 平时第 0 带**不出**；
  - 其余每带概率 `0.04 × (1 + 0.1 × (wave − 1))`。
- 因此**第 1 波在第 2 带有 4% 概率出大怪带**；如果第 2 带是单行，剩余行数只有 1，循环只再放一个单行，不会再判大怪。保护只覆盖第 0 带，没覆盖后续带。
- **v1.14 起第 1 波不再走上面的循环**：整波排成**一个多行方阵带**，行数
  `max(⌈targetRows⌉, firstWaveMinRows = 4)`，在 **t = 0 一次性出生**（见 §4.6.3）。
  - 行数不够 4 行就补到 4 行；`targetRows` 更大时按公式值（带上限 4 行，见 `maxEnemyRowSpan`）。
  - 方阵里**没有大怪、没有 BOSS**，因此第 1 波"第 2 带有 4% 概率出大怪带"这条风险**已不存在**。
  - 每一行仍是"5 列逐列填；35% 放 2 格横，12% 留空，否则 1 格；15% 精英"。
- 大怪带里的大怪固定蓝+品质；4 格 → 小BOSS（×6），6/8 格 → 大BOSS（×15）。

#### 4.6.2 出生位置

```
x = columnCenterX(col) + cols × 128 / 2 − 64
y = 667 − (rowOffset + rows × 0.5) × 128
```

- 所有敌人**盒子顶边恒在 667**，出生瞬间就完整落在屏内：
  - 单格盒 = [539, 667]；
  - 4 行 BOSS 盒 = [155, 667]。
- 不是"从屏幕外走进来"。`GameTuning` 里"盒 = [667, 795]，在可视区之外"的注释是**过期错误**。
- 出生缩放 0.25 s，从 0.6 线性到 1.0；这 0.25 s 内**完全不下落**（只有 `Falling` 消费滚动）。

#### 4.6.3 排期

```
rowGap(秒) = 1.2 × 128 ÷ fallSpeed = 153.6 ÷ fallSpeed
跨带时钟 += max(本带行数, 上一带行数) × rowGap + 上一带错峰预算
带内错峰 = min(0.08, rowGap × 0.5 ÷ 最大列排名)   // 5 列下恒 0.08；第 1 波恒 0（见下）
```

- 第 1 波行距 **5.12 s**；第 8 波 **3.28 s**（首波不再用行距排期，行距只对其余波次生效）。
- **第 1 波（v1.14 起）：整波是一个方阵，全部敌人在 t = 0 出生**（只有一帧的差别），
  不再"3 个单行带、最后一只 t ≈ 10.6 s"。实现上首波**关闭列错峰**（`stagger = 0`），
  否则"不同列、上下相邻"的两只会少吃 `0.08 × 30 = 2.4 px`，同列纵向间距就不是整格了。
- 副作用（需要知道的排期变化）：`updateWaveFlow` 从"本波最后一个敌人出生"开始计 `waveInterval`，
  所以首波瞬间出完后 **第 2 波在 t ≈ 8 s 开始**（v1.15 前是 10 s；v1.14 前是 20.6 s），后续波次也随之整体提前。
- 首波血量：行数 3 → 4（+33%，v1.14）× 每格血量 ×1.2（v1.15）≈ **+60%**（≈ 775 → 1,240）。
  §5.7 那张血量/时长表是 v1.15 之前的读数，**整表未重算**（趋势可用，具体数字作废）。

### 4.7 状态机

| 状态 | 时长 | 缩放 | 位移来源 | 可被击中 | 停世界 |
|---|---|---|---|---|---|
| Spawning | **0.25 s** | 0.6 → 1.0 线性 | 不动 | ❌ | 否 |
| Falling | 直到盒底 ≤ −507 | 1.0 | `y -= scrollDelta` | ✅ | 否 |
| Telegraph | **1.0 s** | 1.0 | 不动 | ✅ | ✅ |
| Diving | 直到命中 / 出屏 | 1.35 → 0.5，0.4 s | 自身 `1120 px/s`，飞向**锁定的**目标点 | ✅ | 否（除非冻结） |
| Dead | 当帧移除 | — | — | ❌ | 否 |

- **越线判据**：`盒底 = y − rows × 128 / 2 ≤ −507`；多格按整块底边，不是每格。
- **俯冲目标只锁一次**：`startDive` 时记录玩家当前位置，之后玩家走开就打空。
- **俯冲命中**：圆心距 ≤ **72 px**；伤害 `min(5 × cells, 40)`。
- **俯冲结束**：无论命中还是落地，都直接 `killEnemy`，**不经过 `damageEnemy`**，所以：
  - 不计击杀数；
  - 不掉落经验 / 金币 / 魂晶 / 超级水晶；
  - 不触发受击闪白/伤害飘字（玩家侧除外）。
- **Telegraph 无表现**：没有描边、没有往复缩放、没有地面阴影；玩家只看到"怪突然停 1 秒，然后冲下来"。
- **放大顺序**：起飞瞬间直接 1.35，再用 0.4 s 缩到 0.5；不是"先放大再起飞"。

### 4.8 世界暂停（全场停止）

```ts
applyStopBlocking(enemies):
    任一敌人 state === Telegraph 或 frozen === true
    → 所有敌人 blocked = true；scrollDelta = 0
```

- 敌人、背景、掉落物**同时静止**；这是"单一滚动源"的直接结果。
- **不是同列阻塞**：`GameTypes.ts` 注释里的 `applyColumnBlocking` 不存在；实际是全局阻塞。没有"同列排队"。
- 后果：
  - 任意一只怪进入 Telegraph，**整个世界停 1 秒**；
  - 多波重叠时，可能出现"刚恢复又停"的连续停顿；
  - 玩家在暂停期间仍可移动、瞄准、接弹；特殊弹 CD 与状态计时照走；
  - 俯冲**不受世界暂停影响**（只受冻结影响），所以"世界停了但俯冲怪还在飞"是当前的真实观感。

### 4.9 状态效果

| 项 | 灼烧 | 冰冻 |
|---|---|---|
| 来源 | 火球命中 | 冰冻弹命中 |
| 时长 | `3.0 + 0.4/级` s | `1.2 + 0.25/级` s |
| 伤害 | 每 0.5 s 跳 `8 + 4/级` | 无持续伤害 |
| 刷新 | 时长与跳伤各自取 max，累计值保留 | 时长取 max |
| 是否暴击 | ❌ | ❌ |
| 计时 | 真实时间，不受世界暂停影响 | 真实时间，不受世界暂停影响 |
| 对世界 | 无 | **全场时停** |
| 表现 | 橙色呼吸遮罩 | 青色呼吸遮罩 |
| 死亡 | `killEnemy` 清状态 | 同左 |

- 灼烧跳伤按 `floor(累计时间 / 0.5)` 结算；一帧内可补多跳，**本帧合计一次结算**。
- 灼烧到期帧只累计"真正在烧的那一段"，不会多算。
- 冰冻**必须**按真实时间走：如果跟着世界暂停，就会"冻住 → 世界停 → 计时不走 → 永久冻住"。
- 冰冻是当前最强的控制：5 级 2.2 s / 2.62 s CD = **84% 覆盖率**，且冻结期间玩家、子弹、CD 全部照常。

### 4.11 攻击手段与 BOSS（设计目标，未实现）

#### 4.11.1 为什么必须补

当前敌人只有俯冲一种攻击，导致：

- 玩家只需要看"谁停了"，不需要分辨攻击类型；
- 远程/激光/冲锋这些"弹幕阅读"的乐趣缺失；
- BOSS 只是"血很厚的俯冲怪"，没有阶段仪式感；
- 8 波里除了最后一只大怪，没有任何里程碑。

#### 4.11.2 四种攻击

| 手段 | 预警 | 伤害 | 弹速 / 范围 | 间隔 | 适用 | 破解 |
|---|---|---|---|---|---|---|
| 射箭 Arrow | 0.50 s 弓身发亮 | 6 | 420 px/s 直线 | 3.0 s | 普通 / 精英 | 横移 |
| 射击 Shoot | 0.60 s 枪口闪光 | 4 × 3 连发 | 520 px/s，轻微预判 | 3.5 s | 精英 / 小BOSS | 变向 |
| 激光 Laser | 0.80 s 红线锁定 | 12 | 全屏直线，宽 24 px，持续 0.25 s | 4.5 s | 小BOSS / 大BOSS | 离开红线 |
| 冲锋 Charge | 0.70 s 后撤 + 红线 | 15 | 640 px/s，撞墙停 | 5.0 s | 精英 / 大BOSS | 侧移 |

**通用规则**：

1. 所有攻击 `windup ≥ 0.45 s`，预警必须在伤害之前可见。
2. 攻击型敌人**不参与俯冲**；俯冲型敌人**不远程攻击**，避免同一只怪两种威胁叠加。
3. 普通敌人默认**不攻击**（保持割草感）；精英起才装配攻击。
4. 攻击预警**不停止世界**；只有"俯冲 Telegraph"停世界。需要把 `blocked` 与 `attackWindup` 拆成两个标志，否则每只远程怪都会让全场卡一下。
5. 攻击型占比曲线：

| 波次 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 攻击型占比 | 0% | 0% | 20% | 30% | 40% | 50% | 60% | 70% |

#### 4.11.3 BOSS 多阶段

| 阶段 | 触发 | 行为 | 持续时间 |
|---|---|---|---|
| P1 | 100% | 基础攻击 + 召唤 2 只小怪 | 直到 66% |
| P2 | 66% | 攻速 +20%，增加激光 | 直到 33% |

**BOSS 血量预算**（关键）：

- 不要再用"15 × 格数 × 品质"直接当 BOSS 血。当前 8 格红 BOSS 在第 8 波是 **33,120 血**；按 250 面板 DPS 要 **132 秒**，还没有算小怪。
- 应按"目标击杀时间 × 当时期望 DPS"反推：
  - 第 4 波小BOSS：目标 **20~25 s**，期望 DPS 80~100 → **1,800~2,500 血**；
  - 第 8 波大BOSS：目标 **35~45 s**，期望 DPS 200~260 → **7,000~11,000 血**；
  - 超过 12,000 一律夹到 12,000（首版）。
- 实现上建议加 `bossHpCap`，并在生成时按 `wave` 取预算，而不是让品质/格数自由相乘。

#### 4.11.4 BOSS 表现

- 顶部独立血条（分 3 段，标阶段阈值）；
- 阶段切换：0.8 s 白闪 + 震屏 + 播放一次音效；
- 死亡：0.5 s 慢放/缩放 + 爆点，再结算掉落；
- BOSS 出场：从顶边完整落下（当前就是屏内出生，可直接复用）。

## 5. 关卡与波次

### 5.1 波次结构

| 项 | 当前值 | 说明 |
|---|---|---|
| 每关波数 | **8** | `wavesPerLevel` |
| 换波间隔 | **8 s** | 从"本波最后一个敌人出生"开始计时（v1.15：10 → 8 s） |
| 是否等清场 | **否** | 出完 + 8 s 就开下一波，残留敌人同场 |
| 同屏上限 | **无** | `maxRows = 12` 只是每波目标行数，不是同屏上限 |
| 最后一波 | 第 8 波 | 出完后若场上还有敌人，不结算；清空后立即过关 |

**这意味着**：

- **v1.14 起**首波整波方阵在 t = 0 一次性出完，第 2 波在 **t ≈ 8 s** 开始（v1.15 前是 10 s）；首波最后一行的单格怪要下落约 24 s 才越俯冲线。所以在 8~24 s 之间，**第 1 波还在下落、第 2 波已经开始**。
- 第 3 波在第 2 波出完 + 8 s（约 **t ≈ 36 s**）开始，此时第 2 波还在下落、第 3 波刚开始 → 2 波同屏。
- 如果玩家清得慢，3 波同屏是可能的；没有任何机制阻止。
- 每只敌人 1~4 个 Sprite 节点 + 状态遮罩 + 闪白模板；40~60 只同屏时，节点数轻松破 300，且**没有对象池**。

### 5.2 出生排期公式

```
rowGap = 1.2 × cellSize ÷ fallSpeed(wave) = 153.6 ÷ fallSpeed
跨带时钟 += max(本带行数, 上一带行数) × rowGap + 上一带错峰预算
带内错峰 = min(0.08, rowGap × 0.5 ÷ 最大列排名)
```

### 5.3 滚动世界

- **单一滚动源**：每帧只在 `updateScroll()` 算一次 `scrollDelta`，敌人、背景、掉落共用。
- 背景优先用 `m_GameBg` 的真实贴图；按图案周期克隆足够块数（1334 高 / 768 周期 = 3 块），接缝做交叉淡入淡出。
- 网格兜底路径的周期固定 **768 = 6 × 128**，保证回绕前后逐像素一致。
- 世界暂停时 `delta = 0`；背景、敌人、掉落一起停。
- 掉落物**锁步**：`drop.y -= scrollDelta`，不额外加速；磁吸是玩家侧行为，独立叠加。

### 5.5 过关与"下一关"（当前 bug）

```
finishLevel():
    showMessageOverlay('第 N 关 完成', '击杀 / 用时 / 金币 / 魂晶',
                       ['下一关', '返回主页'],
                       index => index === 0 ? onRestart() : onExit())
```

- "下一关"调用的是 `onRestart`，而 `GamePanel.restartCurrentLevel()` 会**重开当前关**（`m_Level` 不变）。
- `CommonGameProgress` 只有 `getCurrentLevel()`，没有任何 `setCurrentLevel()` 调用。
- 因此：**关卡永远不会推进**；玩家点"下一关"会回到同一关第 1 波。
- `onLevelClear` 回调虽然被调用，但 `GamePanel` 没有传，等于空转。

**修复建议**（P0）：

1. `BattleOptions` 增加 `onNextLevel(result)`；
2. `finishLevel` 第一个按钮改调 `onNextLevel`；
3. `GamePanel` 收到后 `level + 1`，写入 `CommonGameProgress`，再 `restart(level + 1)`；
4. 增加"关卡上限 / 循环"规则：例如 10 关后进入无尽，或每关 +1 波。

### 5.6 手写关卡（设计目标）

当前 `Level / Wave / Row` 表只有模板，没有运行时读取。建议保留随机为主，但**首波、每 4 波、最终波**用手写模板保证节奏：

| 位置 | 目的 | 手写内容 |
|---|---|---|
| 第 1 波 | 教学 | 3 行白/绿单格 + 1 只双格横；无精英、无大怪、无远程（**v1.14 已实现"4 行方阵 + 无大怪"**；精英 15%、品质未压低仍未实现） |
| 第 4 波 | 第一个小BOSS | 1 只 4 格蓝小BOSS + 2 行杂兵；BOSS 居中 |

**② 大怪节奏**

- 第 1 波：**禁止**任何大怪带（**v1.14 已由"开场方阵"结构性实现**：首波不走大怪带循环；`miniBossChance = 0` 仍可作为配置层保险）；

- 第 3~4 波：3~4%；
- 第 5~7 波：5%；
- 第 8 波：固定 1 只 6 格大BOSS，不再随机 8 格；

**③ 同屏上限**

- 以"占格数"计：**同屏 ≤ 45 格**（约 9 行），或敌人 ≤ 15 只；
- 达到上限时，**暂停下一波生成**，但当前波继续；不要丢弃敌人；
- 上限同时是性能护栏：超过 45 格时不再创建新节点。

**④ 换波条件**

- 从"出完 + 10 s"改为"出完 + 8 s，且当前波剩余 ≤ 40% 或已过 15 s"；**前半（8 s）v1.15 已实现，后半（按剩余比例提前）未做**；
- 这样既保留重叠，又不会叠 3 波；
- 最后一波不变：必须清空。

**⑤ 时长与 BOSS**

- 8 波 → **10 波**，或保持 8 波但每关之间连续（修好"下一关"）；
- 第 4 波加一个小BOSS，第 8 波大BOSS；形成"小里程碑 + 关底"；
- BOSS 血量按 §4.11.3 的 TTK 预算，不再直接乘 15。

**⑥ 确定性**

- 波次生成使用**独立 RNG**（`waveRng`），战斗使用 `combatRng`；
- seed 只控制关卡；这样同 seed 可复现，也方便做无头平衡回归。

## 6. 开局天赋

### 6.1 当前实现

- 进入战斗后，先弹"开局天赋 · 三选一"。
- 选项来自 **同一个 `SKILL_POOL`**（12 个技能），不是独立天赋池。
- 抽取规则：过滤已满级，`RandomUtil.sample` 等概率抽 3 个。
- 选中后立刻应用，然后开始第 1 波。
- 没有刷新、没有 reroll、没有稀有度、没有"必出某类"。

### 6.2 问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 开局就能抽到特殊弹 | 开局随机性过大：抽到火球 = 前 3 波白送，抽到弹速 = 几乎无感 |
| 2 | 开局就能抽到纯后期技能 | 例如暴击伤害 +30%，第 1 波收益极低，等于空过 |
| 3 | 没有"保底 1 攻 1 防 1 机制" | 非酋可能三张全是防御，前 10 分钟打不动 |
| 4 | 与升级三选一共用池 | 开局选择不构成"流派起点"，只是提前拿一张升级卡 |
| 5 | 特殊弹三选一可重复出现 | 三个特殊弹同时开局，配合自动瞄准直接进入"看动画"模式 |

### 6.3 设计目标

开局天赋应该是**流派的起点**，而不是"提前一次升级"。建议独立 8~10 个天赋，效果更"机制化"、数值更克制：

- 每个天赋只做一件事，但改变打法；
- 三张卡保证至少 1 张进攻、1 张生存/功能；
- 特殊弹**不在开局池**，最早第 2 次升级出现；
- 天赋可以被后续技能强化，但不直接给满级数值。

### 6.4 建议天赋池

| ID | 名称 | 效果 | 定位 | 备注 |
|---|---|---|---|---|
| `t_ricochet` | 弹射专精 | 子弹每次弹墙后伤害 +15%，最多叠 3 层 | 进攻/机制 | 鼓励打墙，不是直射 |
| `t_catcher` | 接球手 | 接弹半径 +12 px；接弹后 0.5 s 内下一发伤害 +50% | 进攻/节奏 | 强化"接弹"核心 |
| `t_steady` | 稳定手 | 弹匣 +2；空弹匣时移速 +15% | 功能/生存 | 缓解空窗 |
| `t_close` | 近身战 | 距玩家 200 px 内敌人受到伤害 +25%；玩家受伤 -10% | 进攻/风险 | 鼓励贴脸 |
| `t_frost` | 冷血 | 命中 5 次后，下一次命中冰冻 0.6 s（内置 CD 6 s） | 控制 | 不给冰冻弹，给局部控制 |
| `t_greed` | 贪婪 | 经验 +25%；每升 2 级额外 +1 金币 | 经济 | 长期收益 |
| `t_guard` | 护盾 | 每 20 s 获得 1 层护盾，抵挡一次伤害 | 生存 | 上限 1 层 |
| `t_focus` | 专注 | 站定 1 s 后，暴击率 +15%；移动后失效 | 进攻/站位 | 与走位取舍 |

> 数值是首轮建议，需在 §12 的平衡回归里验证。原则：**开局天赋的强度 ≤ 一次普通升级的 1.5 倍**，但机制差异要明显。

### 6.5 抽取规则

1. 从天赋池抽 3，保证至少 1 张 `进攻`、1 张 `生存/功能`；
2. 不出现与当前 build 完全无关的卡（例如已满级技能对应的天赋）；
3. 开局天赋不可刷新（首版）；后续可加"看广告刷新一次"；
4. 天赋只在本局生效，不带出局外。

### 6.6 与技能/加点的叠加顺序

```
基础值（GameTuning）
  → 外围加点（永久，§9）
  → 开局天赋（本局）
  → 升级技能（本局）
  → 临时 Buff（关卡内，如接弹后 0.5 s）
```

- 加法类先加、乘法类后乘；暴击率/暴击伤害各自夹取上限。
- 所有最终值必须能被 `describeStats()` 打印；调试 HUD 显示最终值，不是基础值。

- 一局约 13~14 次三选一，**只能点满约 22%**，所以 build 差异主要来自"先点哪几条"。
- 特殊弹每种 5 级，三特殊弹全满需要 15 次，而一局约 13 次；正常只能满 2 种，第 3 种要靠超级水晶补级。

### 7.2 抽取与升级规则

```
pickSkillChoices(rng, levels, count=3):
    available = 所有 level < maxLevel 的技能
    return sample(available, 3)      // 等概率，无权重
```

- 满级技能不再出现；如果可升级技能少于 3 个，就全给（不会空卡）。
- 选中后 `markSkillLearned` 夹到上限，防止存档/调试写入 8/5。
- 升级是**暂停世界**的弹层；可以连升，逐层弹。
- 卡片只显示名称、描述、`升级 x/y`；没有图标、稀有度、类型标签、当前值预览。

### 7.3 技能与特殊弹的耦合

- 特殊弹技能不是"被动加成"，而是"解锁一枚自动发射的子弹"。
- 三种特殊弹各自独立 CD、独立等级、同帧可齐射。
- 特殊弹的伤害/时长/目标数**全部现取当前等级**，不缓存在子弹上；升级后下一发立即生效。
- 特殊弹不吃弹匣、不吃接弹；这是它们强于弹匣弹的结构性原因。

### 7.4 设计目标：稀有度、进化、融合

#### 7.4.1 稀有度

| 稀有度 | 颜色 | 抽取权重 | 示例 |
|---|---|---|---|
| 普通 | 白 | 60 | 攻击强化、弹速、拾取范围 |
| 稀有 | 蓝 | 30 | 快速射击、暴击率、生命强化 |
| 史诗 | 紫 | 9 | 接球手、特殊弹 |
| 传说 | 金 | 1 | 进化/融合专属 |

- 权重按"当前等级"动态调整：低级技能权重略高，避免一直抽到不想要的。
- 保底：每 5 次三选一至少出现 1 张史诗+；每 10 次至少 1 张传说（首版可只做史诗保底）。

#### 7.4.2 进化

- 条件：某技能满级 + 持有对应"超级水晶"；
- 效果：替换为进化版，数值提升 + 机制变化；
- 示例：`s_power` 满级 + 1 超级水晶 → `s_power_evo` "穿透弹"：子弹命中后不反弹，继续飞行 0.2 s，对路径上所有敌人造成 50% 伤害。

#### 7.4.3 融合

- 条件：两个指定技能都 ≥3 级 + 2 超级水晶；
- 效果：两个技能合并为一个融合技能，腾出 1 个技能位；
- 示例：`s_lightning` + `s_ice` → "霜雷"：闪电链每跳附加 0.3 s 冻结，但冻结不再全场时停（改为单体）。

> 进化/融合是"后期目标感"的来源，但也是数值爆炸的高发区。首版建议只做 **3 条进化 + 1 条融合**，且必须满足"总倍率 ≤ 10×"的预算（§7.5）。

### 7.5 平衡预算

- 目标：第 8 波 **6,000~8,000 血 / 30~40 s**，有效 DPS 需要 **200~270**。
- 当前：基础面板 ≈31；纯弹匣 13 次约 **150**；单特殊约 **270**；双特殊约 **340**（理论值，未计飞行/空转）。
- 差距：
  - 纯弹匣离目标差 **25~40%**，需要靠多命中/场景，或把第 8 波降到 6,000；
  - 单/双特殊已达标，但特殊弹占 **60~83%**，必须压到 ≤40%；
  - 总倍率（相对基础）当前 **5~11×**，超过 12× 开始秒杀。

### 7.6 当前问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 无稀有度、无权重 | 每张三选一"看起来一样重要"，缺少惊喜 |
| 2 | 无进化/融合 | 满级技能变成"不再出现"，没有终点目标 |
| 3 | 无数值预览 | 玩家不知道 +3 伤害是提升 30% 还是 3% |
| 4 | 特殊弹与普通技能同池 | 抽到特殊弹 = 白送一套自动 DPS，抽不到 = 少一个机制 |
| 5 | 没有刷新/锁卡 | 三张都不想要时只能硬选 |
| 6 | 没有 build 标签 | 无法做"本局流派"回顾，也无法做成就 |

### 7.7 优化建议

1. **给技能加 `rarity` 与 `tags`**（`projectile / crit / sustain / economy / special`），三选一按标签做轻度保底。
2. **首次三选一固定出 1 张机制卡**（特殊弹或接球手），避免开局全是数值。
3. **加"刷新一次"**：消耗金币（例如 20 金），给金币一个出口。
4. **满级技能给"进化提示"**：满级后不再出现在三选一，但满足条件时出现"进化"卡。
5. **卡片显示当前 → 下一级**：`伤害 10 → 13`，而不是只写 `+3`。

## 8. 掉落与成长

### 8.1 四类掉落

| 掉落 | 触发 | 数量 | 价值 | 当前问题 |
|---|---|---|---|---|
| 经验 Exp | **每次击杀必掉** | 1 枚 | `enemyExpValue` | 不随格数增加；BOSS 只有 1 枚 |
| 金币 Coin | 普通 35%，精英/BOSS 100% | 按品质 `[0,1,3,5,6,8]` 枚 | 总值按枚数均分后取整 | **白怪 0 枚 → 永不掉金币** |
| 魂晶 Soul | 精英/BOSS（类型值 > 0 当开关） | 按品质档位：1 / 2 / 6 | 档位 × (档位 + 1) | **配置的 1/3/10 被忽略** |
| 超级水晶 Super | 精英 15%，小/大BOSS 100% | 1 枚（价值 1 或 2） | 用于进化/融合（未实现） | 只有计数，没有消费口 |

**魂晶档位细节**：

```
tier = floor(quality / 2)       // 白绿 0，蓝紫 1，金红 2
unit = tier + 1                 // 1 / 2 / 3
count = max(1, tier)             // 1 / 1 / 2
total = unit × count             // 1 / 2 / 6
```

- 所以"精英必掉 1 魂晶"只对白/绿精英成立；金/红精英掉 6。
- 类型表里的 `typeSoul = [0,1,3,10]` 只用来判断"是不是精英以上"，**不参与数量**。
- 这导致"打高品质精英"的魂晶收益是"打低品质精英"的 6 倍，而旧设计是按类型给 1/3/10。

### 8.2 散落、磁吸、拾取、消失

| 阶段 | 规则 | 参数 |
|---|---|---|
| 生成 | 在敌人位置周围圆形散落，角度随机、半径 `√u × 26` | `dropScatterRadius = 26` |
| 世界位移 | `y -= scrollDelta`，与敌人/背景严格锁步 | 无额外速度 |
| 磁吸 | 玩家中心距离 ≤ 磁吸半径时，以 `magnetSpeed` 向玩家移动；**可以向上吸** | `magnetRadius = 192`（+技能最多 +120 → 312）、`magnetSpeed = 1120` |
| 拾取 | 只有距离 ≤ `pickupRadius` 才结算 | `pickupRadius = 38` |
| 消失 | 越过屏幕底边再往下 **30 px** → `Fell`，**不结算** | `y ≤ -697` |
| 寿命 | 15 s，仅用于表现；**不决定消失** | `dropLifeTime = 15` |
| 暂停 | 世界暂停时掉落物停；磁吸是玩家侧行为，照常 | `dropLifePausesWithWorld = true` |

- **唯一收益路径是进入 38 px 拾取圈**；越过俯冲线、寿命耗尽、滚出屏幕都不给奖励。
- 磁吸范围 192 px 很大，但拾取圈只有 38 px；所以"吸过来"之后还要走到身上。
- 掉落物不合并、不堆叠；一局 20+ 敌人 × 多枚金币，场上可以同时有 100+ 节点。

### 8.3 经验曲线

```
expNeed(n) = round(8 + 6(n−1) + 1.5(n−1)²)
```

| 当前等级 | 升下一级需要 | 累计经验 | 本局大致对应 |
|---|---|---|---|
| 1 | 8 | 0 | 开局 |
| 2 | 16 | 8 | 第 1 波前段 |
| 3 | 26 | 24 | 第 1 波 |
| 4 | 40 | 50 | 第 1 波末 |
| 5 | 56 | 90 | 第 2 波 |
| 6 | 76 | 146 | 第 2 波末 |
| 7 | 98 | 222 | 第 3 波 |
| 8 | 124 | 320 | 第 3 波末 |
| 9 | 152 | 444 | 第 4 波 |
| 10 | 184 | 596 | 第 5 波 |
| 11 | 218 | 780 | 第 6 波 |
| 12 | 256 | 998 | 第 6 波末 |
| 13 | 296 | 1,254 | 第 7 波 |
| 14 | 340 | 1,550 | 第 8 波 |
| 15 | 386 | 1,890 | 满级 build 附近 |

- 全程经验约 **1,595** → 第 8 波结束到 **14 级**，共 **13 次三选一**。
- `s_greed` 每级 +20% 经验；3 级 = ×1.6，会明显提前升级。
- 经验只来自击杀；**俯冲自杀的敌人不给经验**，所以"只躲不打"的玩法不会成长。

### 8.4 升级流程

```
grantExp(stats, gained):
    applyExp(level, exp, gained × expMul)
    → 可能一次升多级
    → m_PendingLevelUps += levels

showLevelUpChoice():
    if pending <= 0: return
    choices = pickSkillChoices(rng, levels)   // 满级过滤
    if choices.length === 0: pending = 0; return
    pending--
    弹三选一（暂停世界）
    选中 → applySkill → 关闭 → 递归 showLevelUpChoice()
```

- 连升多级会连续弹；每层都暂停世界。
- 如果所有技能都满级，`choices.length === 0`，直接清空 pending；但一局只有 13 次，正常到不了。
- 三选一没有"跳过"；必须选一张才能继续。

### 8.5 货币现状

| 货币 | 获取 | 当前用途 | 是否存档 |
|---|---|---|---|
| 金币 | 击杀掉落（白怪 0） | **无** | ❌ 每局重置 |
| 魂晶 | 精英/BOSS 掉落 | **无** | ❌ 每局重置 |
| 超级水晶 | 精英/BOSS 掉落 | **无**（进化/融合未实现） | ❌ 每局重置 |

- `finishLevel` 会显示金币/魂晶；`finishGameOver` 只显示关卡/波次/击杀。
- 两个结算都没有把货币写入 `StorageManager`；`GamePanel` 重开会新建 `BattleView`，计数器归零。
- 因此当前**没有局外成长**，也没有"这一局带出了什么"的实感。

### 8.6 设计目标：给三种货币出口

#### 8.6.1 金币：局内决策

| 出口 | 价格 | 效果 | 目的 |
|---|---|---|---|
| 刷新三选一 | 20 / 40 / 80（每次递增） | 重抽 3 张 | 让"手气差"有补救 |
| 买第 4 张 | 60 | 本次多一个选项 | 给 build 追梦 |
| 锁一张 | 30 | 下次必出 | 做组合 |
| 小回复 | 50 | 回复 20 HP | 救急 |

- 金币不再带出局，避免"攒钱"破坏局内节奏。
- 一局约 500 金币，足够 6~8 次刷新；这是"决策资源"，不是"存款"。

#### 8.6.2 超级水晶：局内进化

| 用途 | 消耗 | 效果 |
|---|---|---|
| 升级技能 | 1 颗 | 技能 +1 级（可超过普通上限 1 级） |
| 进化 | 1 颗 + 满级技能 | 替换为进化版 |
| 融合 | 2 颗 + 两个 ≥3 级技能 | 合并为一个融合技能，腾 1 个技能位 |

- 一局约 6 颗；刚好够 1 次进化 + 1 次融合，或 6 次升级。
- 超级水晶不能带出局，避免 meta 数值膨胀。

#### 8.6.3 魂晶：局外成长

- 只在结算时按"本局获得"写入存档；
- 用于加点、皮肤、召唤；
- 不参与局内数值。

### 8.7 经济估算

| 项 | 每局期望 | 说明 |
|---|---|---|
| 经验 | 1,595 | 到 14 级，13 次三选一 |
| 金币 | 512 | 白怪 0 金币，主要来自绿+与精英 |
| 魂晶 | 56 | 品质档位 1/2/6，不是类型 1/3/10 |
| 超级水晶 | 6.05 | 小/大BOSS 必掉 |
| 击杀 | 约 120 | 8 波合计 |

- 魂晶 56/局，若单节点满级 150，则 **2.7 局**点满一个节点；6 节点约 **16 局**。
- 这比旧文档假设的"15 魂晶/局、16 局点满一节点"快一个数量级；要么提高节点成本，要么降低魂晶产出，否则 meta 很快被点满。
- 金币 512/局，按刷新 20/40/80 递增，大约能刷 4~5 次；合理。

### 8.8 问题清单

| # | 问题 | 影响 |
|---|---|---|
| 1 | 白怪不掉金币 | 前期没有金币收入，刷新/购买系统无法早开 |
| 2 | 魂晶按品质而非类型 | 与"精英 1 / 小BOSS 3 / 大BOSS 10"的设计不一致；金红精英收益过高 |
| 3 | BOSS 只掉 1 枚经验 | 击败 BOSS 的成长反馈弱；旧设计是 2~4 枚 |
| 4 | 货币不存档 | 局外成长完全无法开始 |
| 5 | 无消费口 | 金币/魂晶/超级水晶只是数字 |
| 6 | 掉落物不合并 | 后期节点多，性能与可读性差 |
| 7 | 磁吸 192 / 拾取 38 | 吸到身边却不自动捡，玩家要来回蹭 |
| 8 | 俯冲自杀无掉落 | 玩家躲开所有俯冲但没击杀时，收益为 0，容易困惑 |

### 8.9 优化建议

1. **白怪也给 1 枚金币**（`COIN_COUNT_BY_QUALITY[0] = 1`），或把普通怪掉率提到 50%；否则前期经济是死的。
2. **魂晶回归类型值**：精英 1 / 小BOSS 3 / 大BOSS 10；品质只影响金币与经验，不再影响魂晶。这样"打大怪"有明确收益。
3. **BOSS 经验水晶按格数拆 2~4 枚**，每枚价值 `enemyExp / 枚数`；增强击败反馈。
4. **结算即存档**：`finishLevel` / `finishGameOver` 都把 `souls` 写入 `common_souls`，并记录最高关卡。
5. **金币只做局内**：刷新、买卡、锁卡、回血；不要带出局。
6. **超级水晶只做局内**：升级/进化/融合；不要带出局。
7. **掉落合并**：同位置同类型 0.3 s 内合并为一枚，价值相加；减少节点。
8. **拾取圈与磁吸统一**：磁吸到 60 px 内自动拾取，或把 `pickupRadius` 提到 60；当前 38 太小。

## 9. 外围养成

### 9.1 加点系统（设计）

**入口**：主界面"成长"按钮 → 加点面板。当前 `MainPage` 只有"开始游戏 / 排行榜 / 游戏圈"，没有入口。

**货币**：魂晶（结算获得）。

**节点**（首版 6 个，每个 5 级）：

| 节点 | 每级效果 | 满级 | 定位 |
|---|---|---|---|
| 生命 | 生命上限 +8 | +40 | 生存 |
| 伤害 | 子弹伤害 +1 | +5 | 进攻 |
| 移速 | 移动速度 +2% | +10% | 走位 |
| 经验 | 经验获取 +3% | +15% | 成长 |
| 接弹 | 接弹半径 +2 px | +10 px | 手感 |
| 暴击 | 暴击率 +1% | +5% | 后期 |

**成本**：`cost(n) = ceil(6 × n^1.4)`，n 为当前等级 + 1。

| 等级 | 1 | 2 | 3 | 4 | 5 | 合计 |
|---|---|---|---|---|---|---|
| 单级成本 | 6 | 16 | 28 | 42 | 58 | **150** |

- 6 节点全满 **900 魂晶**；按 56/局 ≈ **16 局**。
- 加点只加基础值，不改变机制；避免"没点就打不过"。
- 允许重置，返还 100%（首版）或 80%（正式）。

### 9.2 皮肤与召唤（设计）

**定位**：收集 + 轻量属性；不做付费抽卡，只用魂晶。

| 稀有度 | 召唤价格 | 属性 | 保底 |
|---|---|---|---|
| 普通 | 120 魂晶 | 无 / 仅外观 | 10 抽必出未拥有 |
| 稀有 | 300 魂晶 | 生命 +2% 或 经验 +2% | 同上 |
| 传说 | 680 魂晶 | 伤害 +3%（上限） | 20 抽必出 |

- 皮肤属性总和 ≤ **3%**，避免"皮肤决定强度"。
- 重复皮肤转为碎片：普通 20 / 稀有 40 / 传说 100；碎片可换指定皮肤。
- 召唤动画 ≤ 3 s，可跳过；结果页显示"新皮肤 / 碎片"。
- 合规：概率公示、魂晶不可购买（或只靠游玩）、未成年人保护。

**当前状态**：无皮肤资源、无召唤逻辑、无入口。

### 9.3 存档

当前只有：

```ts
const CURRENT_LEVEL_KEY = 'common_current_level';
CommonGameProgress.getCurrentLevel(default = 1)
CommonGameProgress.setCurrentLevel(level)
```

- `GamePanel.updateLevel()` 会在打开/重开时写入当前关卡；但**没有任何地方把 level + 1**（§5.5）。
- 没有魂晶、加点、皮肤、最高波次、通关次数、设置。

**建议 schema**：

| Key | 类型 | 说明 |
|---|---|---|
| `common_save_version` | number | 存档版本，用于迁移 |
| `common_current_level` | number | 当前关卡（已有） |
| `common_max_level` | number | 历史最高关卡 |
| `common_souls` | number | 魂晶余额 |
| `common_meta` | JSON | 加点节点 → 等级 |
| `common_skins` | JSON | 已拥有皮肤 id 列表 |
| `common_skin_equipped` | string | 当前皮肤 |
| `common_stats` | JSON | 总击杀 / 总游玩时长 / 总通关 |

**写入时机**：

- 结算（死亡/过关）时写魂晶、最高关卡、统计；
- 加点/购买/换肤时立即写；
- 不要在每帧写，避免小游戏存储抖动。

**迁移**：

- `version = 0`（无字段）→ 补默认值；
- 未知字段保留，不整包覆盖；
- JSON 解析失败 → 回退默认值并上报一次日志，不让玩家卡死。

| 项 | 状态 |

| 魂晶结算与持久化 | ⬜ |
| 加点面板 / 入口 | ⬜ |
| 皮肤资源 / 召唤 | ⬜ |

2. **P2**：皮肤资源与召唤；重复转碎片；装备生效。

## 10. 可配置化

### 10.1 原则

1. **一个数值只有一个真源**：默认值在 `GameTuning.ts`，线上覆盖走配置表；不允许 prefab / 场景 / 视图里再写一份。
2. **代码不读魔法数**：所有平衡相关数字必须来自 `GameTuning` 或配置访问器。
3. **配置必须可校验**：重复键、未知键、类型错、越界、引用缺失、权重为 0，都要在导出/启动时报错。
4. **改表必须能验证**：启动日志打印表版本、键数量、与默认值的差异；关键值可在调试 HUD 查看。
5. **布尔/数组也要有归宿**：不能只支持 number，否则 `aimGuideEnabled`、品质权重、掉落表永远只能改代码。

### 10.2 现状总览

| 层 | 已有 | 状态 |
|---|---|---|
| 代码默认值 | `GameTuning.ts` **142 个键** | ✅ 运行时唯一真源 |
| Excel 模板 | 8 个 Excel（player / enemy / level / skill / drop / meta / skin / tuning） | 🟡 有数据，未接线 |
| 导出产物 | `assets/resources/config/roguelike/` **13 个 .bin** | 🟡 文件在，无人加载 |
| 运行时读取器 | `FlatBuffersRuntime.loadConfig/loadAll` | 🟡 代码在，**0 调用** |
| 访问器注册表 | `ConfigManager.registerAccessor` | 🟡 代码在，**0 调用** |
| 数值覆盖 | `GameTuning.applyTuningValues` | 🟡 代码在，**0 调用**，只认 number |
| 生成代码 | `tools/excel-exporter/generated/*` | ❌ 在 assets 外，import npm `flatbuffers`，与引擎自研 `ByteBuffer` 不兼容 |

**结论**：当前是"**代码硬编码 + 一套未接线的配置管线**"。改 Excel 不会影响游戏；改 `GameTuning` 才会。

### 10.3 关键错位（接线前必须修）

| # | 问题 | 现状 | 风险 |
|---|---|---|---|
| 1 | `DropKind` 枚举顺序相反 | Excel：0=经验、1=超级水晶、2=金币、3=魂晶；代码：0=Exp、1=Coin、2=Soul、3=SuperCrystal | 直接导入会把金币/魂晶/超级水晶全部错位 |

| 3 | 同名键取值冲突 | `maxSubStepDistance` 表 8 / 代码 13；`hitShakeAmplitude` 表 3 / 代码 5 | 接线后手感突变、可能穿模 |

| 5 | 玩家字段多余 | `player.xlsx` 有 `moveSpeed=512`、`visualRadius=56`，代码不用（拖拽移动） | 策划以为能调移速，实际无效 |

### 10.4 建议的配置分层

| 层 | 内容 | 读取时机 |
|---|---|---|
| **A. 启动常量** | 分辨率、格子、屏幕边界、层级、颜色 | 编译期常量，不进表 |

| **C. 内容表** | 品质、敌人定义、技能定义、掉落规则、关卡/波次/行模板 | 进入玩法前加载，注册访问器 |

### 10.5 表结构建议

**Tuning**

| 列 | 类型 | 说明 |
|---|---|---|
| key | string | 必须与 `GameTuning` 字段 1:1 |
| value | float | 数值 |
| type | enum | number / bool / intArray / floatArray / string |
| group | string | board / player / bullet / enemy / wave / drop / skill / ui |
| min / max | float | 校验范围 |
| desc | string | 中文说明 |

> 布尔与数组必须显式支持；否则 `aimGuideEnabled`、`dropLifePausesWithWorld`、品质权重永远只能改代码。

**Drop**

- `kind` 用**字符串枚举**（`exp / coin / soul / super`），不要用 0/1/2/3；或者在导出时做显式映射表。
- `amountMin/amountMax` 与代码的"按品质枚数"二选一，不能两套并存。

**Skill**

- 增加 `kind`（active/passive/special/talent）、`rarity`、`weight`、`tags`、`evolveInto`、`fusePartners`。
- `Skill_Effect` 用 `target / op / perLevel / base / cap` 表达，不要每条技能写死 `apply` 闭包；否则表永远追不上代码。
- 特殊弹的 CD/伤害/时长也走 `Skill_Effect` 或独立 `SpecialBullet` 表。

**Level / Wave / Row**

- `Row.template` 用 5 个槽位 + `|` 分隔；`-` 表示被相邻锚点占用，`_` 表示故意留空。
- `Wave.mode` 支持 `random / template / hybrid`；`hybrid` 时手写行优先、剩余随机补。
- `Level` 支持 `isEndless`、`hpMul`、`speedMul`，为后续无尽/难度选择留口。

### 10.6 校验清单

导出/启动时必须检查：

- [ ] 重复 key；
- [ ] 未知 key（表里有、代码没有）；
- [ ] 缺失 key（代码有、表里没有，是否允许用默认值）；
- [ ] 类型不匹配（number 表填了字符串）；
- [ ] 范围越界（负血量、0 间隔、权重为负）；
- [ ] 引用完整性（Enemy.quality 必须存在于 Quality；Skill_Effect.skillId 必须存在）；
- [ ] 权重和 > 0（品质/类型/体型/技能）；
- [ ] 行模板格数 = 5，`-` 必须能追溯到锚点；
- [ ] BossPhase 的 hpThreshold 严格递减，且首尾为 1 / >0；
- [ ] DropKind 映射唯一且完整；
- [ ] `maxSubStepDistance / maxSubStepCount` 与弹速匹配（弹速 × 最大帧长 / 子步 ≤ 半径）。

| 阶段 | 动作 | 验收 |
|---|---|---|
| **P0** | 冻结 `GameTuning`；启动打印键数量与版本；修正 DropKind 映射；删除死键（`catchRadius`、`freeBulletMax`、`*MinCd`） | 日志能看出"这局用了哪套数值" |

### 12.2 玩家 DPS 估算

基础单目标：

```
DPS = 10 / 0.35 × (1 + 0.15 × 0.6) ≈ 31.1
```

13 次升级的几种典型分配（未计弹射多命中、特殊弹飞行时间）：

| 场景 | 分配 | 面板 DPS | 第 8 波 12,000 血需要 |
|---|---|---|---|
| 纯弹匣 | 伤害 5 + 射速 5 + 暴击 3 | **149** | 80 s |
| 单特殊 + 弹匣 | 火球 5 + 伤害 5 + 射速 3 | **268** | 45 s |
| 双特殊 | 火球 5 + 闪电 5 + 伤害 3 | **343** | 35 s |
| 三特殊 | 需要 15 次，**一局只有 13 次** | 不可达 | — |

- 纯弹匣在第 8 波明显不够；特殊弹不是"可选强化"，而是"通关必需"。
- 双特殊 build 的 343 DPS 里，特殊弹占 **284（83%）**；弹匣弹只剩 59。这会让"接弹"这个核心操作变得无关紧要。
- 如果按"特殊弹占 ≤40%"设计，双特殊的总 DPS 应压到 **~150**，或者把第 8 波血量降到 **6,000~7,000**。

### 12.3 特殊弹强度

| 特殊弹 | Lv1 总伤 | Lv5 总伤 | Lv5 CD | Lv5 折算 DPS | 占双特殊 build |
|---|---|---|---|---|---|
| 闪电 | 34 | 222 | 1.80 | 123 | 36% |
| 火球 | 64 | 264 | 1.64 | 161 | 47% |
| 冰冻 | 10 | 26 | 2.62 | 9.9 | 3% + 84% 时停 |

- 火球是"最稳定的单体 DPS"；闪电需要 7 个目标才打满；冰冻的伤害可以忽略，价值全在时停。
- 冰冻 5 级覆盖率 **84%**；考虑飞行/回收时间，实际可能 **>90%**。配合 2 s 自动瞄准，玩家可以几乎不操作。
- 三种特殊弹同帧齐射：如果玩家靠超级水晶把三种都点到 5 级（15 次），一波开场可以瞬间叠 **512** 点基础伤害（未计暴击/连锁/灼烧）。

### 12.7 无头回归

建议加一个纯逻辑脚本（不依赖 Cocos）：

1. 固定 20 个 seed，模拟 8 波生成；
2. 输入一条"玩家 DPS 曲线"（第 1 波 31，第 4 波 120，第 8 波 260）；
3. 输出每波：总血、清场时间、是否溢出、同屏峰值、经验/金币/魂晶；
4. 断言：
   - 第 1 波清场 ≤ 18 s；
   - 第 8 波清场 ≤ 50 s；
   - 同屏峰值 ≤ 15 只；
   - 第 8 波总血 ≤ 8,000；
   - 经验总量 1,400~1,800（13~14 级）。

这比"进游戏打一局"快 100 倍，而且能在改表前就发现回归。

## 13. 优化路线图

### 13.1 排期原则

1. **先修断点，再调平衡，最后加内容**：玩家能感知的"下一关不前进 / 奖励不保存"优先于"某张卡 +3 还是 +4"。
2. **每个 P0 必须有可验收的结果**：不是"改了代码"，而是"点下一关真的进第 N+1 关"。
3. **平衡改动必须带无头回归**：固定 20 个 seed，先跑数据，再进游戏。
4. **一次只改一组数值**：特殊弹、波次、BOSS 分开验证，避免"改完不知道是哪一刀生效"。

### 13.2 P0：下一版必须修（1~2 天）

## 14. 验收标准

### 14.1 原则

- 每条验收必须**可观察、可复现、可量化**；不接受"感觉差不多了"。
- 逻辑层用 Jest；表现层用固定 seed 的手动清单；性能用真机（中端安卓）。
- 任何"设计目标"在实现前只能标 ⬜，不能写进已完成验收。

### 14.2 系统验收清单

#### 子弹

- [ ] 子弹只有"被接住"才会消失；撞墙/撞敌/波次结束都不消失。
- [ ] 顶/左/右墙镜面反射，速率不变；底墙不反射，转入回身。
- [ ] 回身穿透敌人，不造成伤害、不被弹开、每子步重新锁定玩家。
- [ ] 8 s 未回身自动回身；回身强制 `armed`。
- [ ] 接弹半径 = 45 + 16 + 技能加成；子步检测，不穿模。
- [ ] 一次接触窗口内同一敌人只结算一次；2 格/4 格敌人只扣一次。
- [ ] 特殊弹不占弹匣、同时 1 发、CD 飞行中照走、回收同帧可再射。
- [ ] 特殊弹 5 级数值与表一致；CD 下限不再是无用键（或删除）。

#### 敌人

- [ ] 6 品质数值与权重正确；第 1 波无紫/金/红。
- [ ] 4 类型倍率正确；4 格=小BOSS、6/8 格=大BOSS（或改为可配置）。
- [ ] 6 体型中至少 5 种能生成；`DoubleV` 要么生成、要么从文档删。
- [ ] 血量公式 = 品质 × 格数 × 类型 × 波次，下限 1。
- [ ] 俯冲：盒底 ≤ −507 触发 → 1 s Telegraph → 1120 px/s → 72 px 判定 → 5×格数（≤40）。
- [ ] Telegraph 有可读表现；世界暂停时俯冲仍飞（或明确改为停）。
- [ ] 俯冲自毁不掉落、不计击杀（若保留，需要 UI 说明）。
- [ ] 冰冻只停该敌人或全场，但计时按真实时间，不会永久卡死。

#### 波次 / 关卡

- [ ] 8 波；每波目标行数 4 + 0.6(N−1)，实际行数按带溢出。
- [ ] 第 1 波无大怪；大怪从第 3 波开始。
- [ ] 同屏 ≤15 只 / 45 格；超出暂停生成，不丢怪。
- [ ] 换波 8 s + 剩余 ≤40% 或 15 s；无 3 波同屏。
- [ ] 第 8 波清空才过关；死亡/过关都结算。
- [ ] "下一关"真的 +1，并写入存档；到上限后进入无尽/循环。
- [ ] 固定 seed 可复现波次（波次 RNG 与战斗 RNG 分离）。

#### 成长

- [ ] 经验曲线 `round(8+6(n−1)+1.5(n−1)²)`；1595 经验到 14 级。
- [ ] 升级三选一：满级过滤、连升连弹、暂停世界、选完恢复。
- [ ] 13 次升级；纯弹匣/单特殊/双特殊三种 build 都能通关（或明确至少两种）。
- [ ] 金币有出口（刷新/买卡/锁卡/回血）；一局能花掉 300+。
- [ ] 超级水晶有出口（升级/进化/融合）；UI 可见。
- [ ] 魂晶结算入库；主界面可见余额。

#### 外围

- [ ] 加点 6 节点 × 5 级，单节点 150 魂晶；效果进入 `RunStats`。
- [ ] 皮肤可获取/装备；属性 ≤3% 或纯外观。
- [ ] 存档 schema 有版本号；迁移/损坏回退不卡死。
- [ ] 主界面有"成长"入口；排行榜能读到最高关。

#### UI / 表现

- [ ] HUD：关卡/波次、经验、血、弹匣、特殊弹 CD；无调试行。
- [ ] BOSS 血条 + 阶段刻度。
- [ ] 俯冲 Telegraph、敌人血条、死亡动画至少各有一版。
- [ ] 结算显示：关卡、波次、击杀、用时、金币、魂晶、超级水晶、本局技能。

- [ ] 13 个 bin 至少 Tuning 被真实加载。

#### 性能

- [ ] 同屏节点 ≤200；伤害飘字 ≤12；掉落 ≤80。

- [ ] 包体：配置 bin 总大小 < 100 KB（当前约 25 KB）。

| 4 | StatusEffects「applyFreeze」 | `e.frozen === false` | `undefined` | `applyFreeze` 不再直接写 `e.frozen`，要等 `stepStatus` 才写；测试循环没跑 |
